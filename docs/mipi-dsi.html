MIPI DSIDISPLAY SERIAL INTERFACE & D-PHY PHYSICAL LAYER

一根差分对上住着两个灵魂：LP 用 1.2 V 单端大摆幅慢吞吞地发命令、读寄存器； HS 用 200 mV 微弱差分每秒上吉位地倾倒像素。手机屏幕点亮的每一帧， 都要在两种状态间换挡几十次。往下滚动，亲手触发 LP → HS 的换挡，看 SoT 同步码如何对齐一整条显示流水线。

01

它是什么，为什么需要它

What & Why

一句话：MIPI DSI 是把「像素流」打成包、走 D-PHY 差分低压通道送到屏幕的显示接口——命令与像素同一条线，还能反向读回。

MIPI 联盟（2003 年由 ARM / Nokia / ST / TI 等发起）给手机内部定了一套「积木」：协议归协议、物理层归物理层。 显示用 DSI，摄像头用 CSI-2，传感器低速双线用 I3C，数字音频用 SoundWire——它们全都躺在同一套 D-PHY / C-PHY 物理层上跑。 所以吃透本页 03 节的 D-PHY，摄像头那半边（CSI-2 页）等于免费学会一半。

为什么屏不能继续用老接口？看演进链：MCU 屏时代直接写显存（8080/9341 那一代，见 I²S 页同期的并口思路）； 到 RGB 并口（RGB 页），SoC 用 PCLK + HSYNC/VSYNC/DE + D0–D23 共 28+ 根线「推」像素——线多、单端大摆幅、EMI 灾难，帧率一高就走不通； LVDS（LVDS 页）把并口串行化成差分对，EMI 降了，但它只是「透明的线」：没有命令、没有回读、没有包。

DSI 把三条路并成一条：低速时是命令线（LP 模式发 DCS 命令、读寄存器），高速时是像素传送带（HS 模式 4 lane × 最高 2.5 Gbps）。 引脚从 28+ 缩到 10 根以内，功耗和 EMI 同时下降，还能在屏上电、初始化、报错时双向对话——这就是它能统治手机/平板/车载屏的原因。

FACT / A

一条线两个世界 LP / HS

LP：1.2 V 单端、大摆幅、≤10 Mbps，发命令足够；HS：200 mV 差分、80 Mbps–2.5 Gbps，倒像素专用。省电与高速不可兼得？D-PHY 说可以。

FACT / B

一切以包为单位 4B / 长 包

短包固定 4 字节（DI + 2 数据 + CRC16）；长包包头带汉明 ECC、包尾带 CRC16。连同步事件（HSS/VSS）也是一个短包。

FACT / C

双向不是吹的 BTA

LP-11 → LP-10 → LP-00 后主机释放，面板接管 D0± 反向发送：ACK、错误报告、DCS 寄存器读回都靠它。

FACT / D

一条总线多路流 VC

包头 DI 里 2-bit Virtual Channel，允许一条 DSI 链路分时服务多块屏 / 多个数据流（DSI-2 扩展到 4 个 VC）。

02

信号与 Lane · 差分对拓扑

Signals & Lanes

DSI 的物理世界简单到优雅：1 条 CLK± 差分对 + 1–4 条数据差分对，仅此而已。 每张卡片里是正在运行的实时波形（绿线 = D+，琥珀线 = D−）。

CLK ±差分时钟 · 单向CLOCK

主机专供的差分时钟，DDR：每个边沿采一位，一个时钟周期 = 2 UI。频率是 lane 速率的一半（1 Gbps → 500 MHz）。连续模式常振；非连续模式随突发起停、空闲时回 LP-11 省电：

f(CLK) = lane 速率 ÷ 2 · 例：800 Mbps → 400 MHz
D0 ±数据 lane 0 · 双向DATA0

唯一必须存在、也是唯一双向的 lane：上电初始化的 DCS 命令、BTA 换向后的回读全走它。上图循环回放一次 LP→HS→LP 换挡——注意 HS 段（窄带）只有 LP 段约 1/6 的摆幅：

LP 摆幅 1.2 V 单端 ↔ HS 摆幅 200 mV 差分
D1~D3 ±可选数据 lane · 单向DATA1-3

带宽不够就加 lane：字节交错分配（字节 0 走 D0、字节 1 走 D1……），不是位拼接。上图是 D1 在 LPDT 逃逸模式下发 DCS 命令：LP-01 = 0、LP-10 = 1，慢速但极省电：

总带宽 ≈ N × lane 速率 × (8÷10 编码几乎无损)
VDDIO · 保护供电 · ESD · 布线AUX

差分对不需要外部端接电阻——HS 终端（约 100 Ω 差分）在 RX 芯片内部，进入 HS 才打开，LP 时关掉省电。ESD 二极管必须低电容（<0.5 pF），普通 TVS 会把眼图吃没：

4 × 1000 Mbps = 500 MB/s
差分线总数 10 根 引脚（含电源/地约 14） 每 lane 承担 25% 字节流 CLK ± 永远在 · D0 ± 永远在 · 其余按需布线
D-PHY 线态字典（背下来，逻辑分析仪上直接用）： LP 线态按 D+ D− 电平命名：LP-11 = Stop/空闲（双上拉 1.2 V）、LP-01/LP-10 = LP 数据 0/1（也是 HS 前导）、LP-00 = 双低「特殊态」（HS 请求 / 逃逸入口 / TA）； HS 线态按差分极性命名：HS-0（D+<D−）、HS-1（D+>D−）。另有 ULPS（超低功耗，LP-10→LP-00 保持）与 HS-Rqst（= LP-00 持续 T_LPX）。

D-PHY 实验室 · LP 与 HS 的换挡

D-PHY LP/HS Lab
⇄ 本节基础被 CSI-2 页（摄像头）整章复用 —— 摄像头与屏幕共用同一套 D-PHY 时序，读透这里，CSI-2 只剩包格式差异。

这是本页的灵魂。上半部分对比两种状态的电平世界；下半部分是一台「双通道虚拟示波器」， 逐段回放 LP↔HS 切换的完整时序：三种场景可切换 —— HS 突发、LP 逃逸命令、BTA 双向换向。 用 ⏮ ⏭ 单步走一遍，每一段的电压、时序参数、协议含义都会在右侧读出。

LP 态 · 大摆幅慢世界

LOW-POWER 1.2 V
单端 0 / 1.2 V，摆幅 1.2 V，速率 ≤10 Mbps。驱动电流小、接收是比较器对电源轨——发命令、保持、逃逸模式都在这。D+ 与 D− 都是被上拉拽着的「真实电压」。

HS 态 · 小摆幅快世界

HIGH-SPEED 200 mV
差分 ±100 mV（共模 ~200 mV），眼图实时叠加中。80 Mbps–2.5 Gbps。RX 打开内部 ~100 Ω 终端、用差分比较器判决——像素流专用。差分抵消共模噪声，这是它敢用 200 mV 的底气。

11 · 01 · 00 · 同步码HS 四拍口诀

进 HS 永远是四拍：LP-11（歇）→ LP-01（预告）→ LP-00（HS-Rqst，RX 开终端）→ SoT 00011101（对齐），然后才是载荷； 出 HS 一拍 T_HS-TRAIL → LP-11。每次突发这套握手约 1 µs——所以视频流把整行像素打包进少数几个长包，而不是一包一位。

04

数据包解剖 · 逐字节流过 lane

Packet Anatomy

DSI 的协议层只有两种包：短包固定 4 字节（DI + 2 数据 + CRC16），装得下一条 DCS 命令； 长包 = 4 字节包头（DI + 字数 WC×2 + ECC）+ 载荷 + 2 字节 CRC16。 点击「发送」，看字节逐个流过校验门；试试 注入 1 位错，看 ECC 如何定位、CRC 如何兜底。

短包

Short Packet · 4 字节

SHORT WRITE
DI 高 2 位是 VC（虚拟通道），低 6 位是 DT（数据类型）。DCS 短写（DT=0x05/0x15）把命令塞进 2 个数据字节——sleep_out、set_display_on 这类点火命令全是短包。短包没有 ECC。
长包

Long Packet · 包头 + 载荷 + 包尾

LONG WRITE
包头 4 字节：DI + WC 载荷字数 + ECC；然后 WC 字节载荷（像素流 / 初始化序列 / 写显存）；包尾 2 字节 CRC16（覆盖载荷）。ECC 只保包头，CRC 只保载荷——各管一段。
ECC

汉明 SECDED · 纠 1 位检 2 位

HAMMING 24+8
ECC 用 8 位汉明码覆盖包头 24 位（5 位定位 + 1 位总校验）：单比特错自动定位纠正，双比特错检出。为什么只保包头？包头一错整包报废，载荷错还有 CRC 与上层重传兜底。
DCS

点火三连 · 屏的唤醒序列

DCS COMMANDS
面板上电后要先「点火」：0x11 sleep_out → 等 ≥120 ms → 0x29 set_display_on，之后才有像素。命令可以走 LP（逃逸模式，省电）或 HS（快）。顺序、延时错一点——白屏。

Linux 上的 DSI · DRM 实战

Linux Cheat Sheet

DSI 在 Linux 里归 DRM 子系统管：mipi-dsi host 控制器驱动 → panel/bridge 驱动 → CRTC 编码器。 面板的「点火的序列」住在 panel 驱动（如 st7701 / ili9881c / nt35595）或厂商 init 数组里。 点击任意命令行即可复制。

dmesg — 绑定链路是否成立
$ dmesg | grep -iE 'dsi|panel|drm'

st7701: supplying 1 modules? no — panel attach on DSI channel 0
[drm] Initialized rockchip 1.0.0 ... on minor 1
# 没有 bound 消息 → dts 的 ports/endpoint 图没连上

$ ls /sys/class/drm/ | grep -i dsi

$ cat .../card0-DSI-1/{status,enabled}

$ cat .../card0-DSI-1/modes # 面板声明
1080x1920 60.00
modetest — 绕过合成器直接点屏
# 列 connector 找到 DSI-1 的 id，比如 42
$ modetest -M rockchip -c
$ modetest -M rockchip -s 42@25:1080x1920@RG24
# 能出测试图 → 内核链路 OK，问题在用户态（合成器/HAL）
# 出不了图 → 回 08 节：时序、init、settle

DTS — host 控制器 + panel 节点（通用示例）
/* host 控制器：SoC 侧 D-PHY + 包打包器 */
&dsi0
{

};
ports { port@1 { dsi0_out: endpoint { remote-endpoint = <&panel_in>; }; }; };
};
/* bridge 转接（DSI→HDMI/RGB 转换芯片 lt9611/tc358762 等）用 ports 图把两端 endpoint 连起来 */

踩坑指南 · 症状 → 病因

Troubleshooting

DSI 的故障没有热插拔兜底，全靠对号入座。按症状找病因，再回 03 节看波形验证。

白屏
背光亮
初始化序列没生效 · LP 命令无响应

背光亮说明电源 OK，屏没「醒」：查 sleep_out(0x11) 后有没有等够 120 ms、init 序列与面板型号是否匹配、复位脚时序。若逻辑分析仪抓到 LP-11 常挂——命令根本没发出去：查控制器是否配成 LP 发送、D0± 是否接对（命令只走 lane 0）。

花屏
绿条·偏色
settle time 配错 · lane 顺序/极性反

SoT 后前几个字节错、后面全错 = T_HS-PREPARE/T_HS-ZERO（俗称 settle）不匹配；固定错位 = D1/D2 接反或 P/N 极性反；只错一种颜色 = 字节序/像素格式（565 vs 888）配错。先降速率复测：错误消失即是时序裕量问题。

间歇花屏
高帧率才坏
HS 速率超过面板能力

面板 datasheet 标 max lane rate（常见 500–1000 Mbps），SoC 却按 06 节算出的速率直发。症状：60 Hz 正常、90 Hz 起花。解法：加 lane、降 bpp（RGB888→565）或启用 burst 压缩（DSC）。

读回全 FF
无 ACK
BTA 未使能 / 面板不支持回读

发 0x0A get_power_mode 读回全是 0xFF：控制器没开 BTA、没先发 Set Max Return Packet Size，或该面板根本不支持回读（低端屏常见）。用示波器看 D0± 上有没有 LP-10→LP-00 换向序列即可确诊。

睡醒黑屏
resume 未重走初始化 · D-PHY 卡死

suspend 时进了 ULPS 或断了电，resume 只唤醒了主机没唤醒链路：表现为 dmesg 无错但永远黑屏。规范做法是 resume 回调里完整重发 init 序列 + 复位 D-PHY；卡死在 ULPS 时要先发 Mark-1(LP-01) 唤醒序列。

充电/触摸
时花屏
ESD / EMI 侵入差分对

HS 只有 200 mV 摆幅，共模噪声一大眼图就闭：ESD 二极管必须低电容（<0.5 pF，普通 TVS 会毁掉眼图）、差分对下方参考地完整、与充电/天线区拉开或加共模扼流圈。FPC 转接处等长 ±10 mil。

settle time 深讲（D-PHY 四参数）：数据 lane 的 T_HS-PREPARE ≥ 40ns+4UI（驱动 HS-0 让 RX 校准）、T_HS-ZERO ≥ 145ns+10UI、 T_HS-TRAIL ≥ max(8UI, 60ns+4UI)、时钟 lane 的 T_CLK-PREPARE = 38–95ns。 SoC 侧以寄存器/属性出现：Rockchip 叫 phy_timcon / hsfreqrange、i.MX 8 叫 HSFREQRANGE、DW DSI 叫 hw timing。配小的症状：RX 还没校准完 SoT 就到了，前几位错；配大的症状：突发间隔不够，包粘连。先按面板/PHY 手册的速率表抄，再微调。

六条铁律GOLDEN RULES
  • 1空闲 = LP-11：双线上拉 1.2 V，谁都不驱动，这是所有序列的出发点
  • 2进 HS 三段式：LP-11 → LP-01 → LP-00，每段 T_LPX ≥ 50 ns，一步不能省
  • 3SoT = 00011101：没有同步码，RX 的串并转换无从对齐，整包报废
  • 4短包无 ECC，长包 ECC 保头、CRC 保尾：汉明纠 1 检 2，CRC-16/CCITT
  • 5命令只走 D0±，加 lane 只加速像素；读回先发 0x37 再 BTA
  • 6CLK 是 DDR：每 UI 一位、双沿采样，f(CLK) = lane 速率 ÷ 2
术语表GLOSSARY
SoT / EoT
Start/End of Transmission：HS 突发的同步码起点 / 结束（含 T_HS-TRAIL 收尾）
BTA · Bus Turn-Around
LP-11→LP-10→LP-00 后主机释放、从机接管 D0± 的换向过程，双向读回的基础
LPDT · LP Data
LP 模式数据传输：0 = LP-01、1 = LP-10，经逃逸模式进入，≤10 Mbps
ULPS
Ultra-Low Power State：双线保持 LP-00 的微安级休眠，退出需 Mark-1 唤醒序列
DI / DT / VC
Data Identifier = VC(2bit) + DataType(6bit)，每个包头第一个字节
WC · Word Count
长包包头里的载荷字节数（16 bit）
ECC / CRC16
汉明 SECDED（覆盖 24 bit 包头）/ CRC-16-CCITT 0x1021（初值 0xFFFF，覆盖载荷）
GRAM
面板内置显存，Command mode 的存在前提；Video mode 面板可省掉
TE · Tearing Effect
面板回传的帧扫描完成信号，Command mode 下主机据此写入防撕裂
non-burst / burst
Video mode 同步方式：前者 HS 占满行周期，后者压缩发送换取 LP 空闲
