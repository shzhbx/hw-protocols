01

它是什么，为什么需要它

What & Why

一句话：PCIe 是把共享并行总线 PCI 拆成「串行差分 + 点对点 + 交换 fabric」的包协议网络——每条链路独享带宽，靠分层协议保证可靠传输。

老 PCI 是一根共享并口：32 位地址/数据复用（AD0-AD31），33 MHz，总线上所有设备 分时抢线，还要靠 arbiter 仲裁。理论 133 MB/s 是全总线合计—— 设备越多，每人分到的越少；并行线在 66 MHz 以上被走线偏斜（skew）卡死，加宽到 64 位又让主板布线成本爆炸。

2003 年 PCI Express 换了个思路：数据串行化、走差分对（抗共模干扰）、 点对点连接（没有抢线）、时钟嵌入数据流（8b/10b 保证足够跳变，无需单独时钟线）。 需要挂多个设备？用 Switch 织成 fabric。带宽不够？把 N 个 lane 捆绑成 x1/x4/x8/x16—— 这就是「可伸缩」的由来。

一个 lane = 1 对 TX 差分 + 1 对 RX 差分，共 4 根线，两个方向独立（双单工）。 Gen1 每个 lane 单向 2.5 GT/s，经 8b/10b 后有效 250 MB/s； x16 就是 16 倍。今天 GPU、NVMe、万兆网卡、WiFi（见 SDIO 的表亲们） 全都跑在这套 fabric 上。

FACT / A

差分对 · 抗干扰的底牌 TX± RX±

一根线传信号、一根传反相，接收端取差值——电源纹波与外部噪声同时耦合到两根线上，相减即消。摆幅不到 1V，却能跑 32 GT/s。

FACT / B

嵌入式时钟 8b/10b

每 8 bit 编成 10 bit，保证 0/1 跳变密度，接收端从数据流里恢复时钟。Gen3 起改用 128b/130b + 扰码，开销从 20% 降到 1.5%。

FACT / C

包协议 · 事务可拆分 Split Transaction

读请求（MRd）与应答（CplD）是两个独立包，中间链路可以干别的活——不像 PCI 一个总线周期从头占到尾。延迟因此被摊薄。

FACT / D

热插拔与重训练 LTSSM

链路状态机 Detect→Polling→Configuration→L0 全自动：插入、复位、掉速恢复都由硬件自己完成，软件只看见「设备出现/消失」。

02

三层协议栈 · 一个 TLP 的封装之旅

Protocol Stack

PCIe 把 PCI 的「一次总线事务」拆成三层流水线：事务层造包，数据链路层保证包不错不丢，物理层把包变成差分比特流。 发送方向层层加壳，接收方向层层剥壳。

TL事务层 Transaction Layer

组装 / 解析 TLP：3DW 或 4DW 头（Fmt/Type/TC/Tag/Length…）+ 可选数据 + 可选 ECRC。管理请求-完成配对（Tag）、流量分类（TC→VC）、排序规则。设备「人格」全在这一层。

DLL数据链路层 Data Link Layer

给 TLP 加 12-bit SEQ + 32-bit LCRC，压进重传缓冲区；用 ACK/NAK DLLP 实现硬件自动重传；跑 credit 流控（§05），保证永不发送接收方装不下的包。可靠性的老家。

PHY物理层 Physical Layer

加 STP/END 成帧令牌，Gen1/2 做 8b/10b 编码，Gen3+ 做 128b/130b + 扰码；串行化后从差分对打出。链路训练（LTSSM）也住在这里——它是 §04 的主角。

+为什么 ECRC 与 LCRC 并存

LCRC 只保证每一段链路无错；TLP 穿过 Switch 时会被剥壳检查再重新加壳。要验证端到端（RC 到最终 EP）的完整性，得靠事务层的 ECRC——中间节点不碰它。

流量控制 · credit 记账

Credit-Based Flow Control

为什么不能无限速发 TLP？因为接收缓冲是有限的。PCIe 不用握手线，而是「记账」： 接收方用 InitFC/UpdateFC DLLP 广播剩余额度（posted / non-posted / completion × 头 / 数据，共 6 本账）， 发送方花完 credit 就停。切换两种模式，看无限速的下场。

溢出的 TLP 不会消失——它触发 NAK 重传，把带宽浪费在重发上，最坏情况接收方缓冲长期满、链路「假死」。 credit 机制让发送速率自动贴合消费速率：流控是链路层的义务，不是可选项。 这也是「MPS（Max Payload Size）调大为什么常能提速」的根源——单位 credit 摊到更多字节。

Enumeration & BAR

链路训练好只是「通了电」；固件还要枚举：从总线 0 出发深度优先扫描，读每个位置的 Vendor ID， 遇到桥就给它分配下级总线号；再用 BAR 探测尺寸，把每块设备的寄存器/FIFO 映射进统一内存地图。 点击左侧树里的设备，右侧看它的配置头与 BAR 落位。

三级寻址：8 bit 总线（256 条）× 5 bit 设备（每总线 32 个）× 3 bit 功能（每设备 8 个）。 独立显卡是 01:00.0，NVMe 可能是 03:00.0——这就是 lspci 输出里冒号串的含义。 桥的 secondary/subordinate 总线号把树延展开来；现代系统用 ECAM（MMCFG）把 4 KB 配置空间直接映射进内存， 地址 = 总线<<20 | 设备<<15 | 功能<<12。

  • 4读要回票（Non-Posted + CplD），写不回头（Posted）——性能与语义的关键分叉
  • 5credit 花光就停发——流控是链路层义务；MPS 越大单位信用摊得越薄
  • 6LCRC 管一段链路，ECRC 管端到端——穿过 Switch 时会被重新封装
  • 7带宽 = lanes × GT/s × 编码效率 ÷ 8——先算理论值再谈优化

术语表
TLP
Transaction Layer Packet，事务层包：头 + 可选数据 + 可选 ECRC，软件世界的"业务报文"
DLLP
Data Link Layer Packet，链路层包：ACK/NAK/流控（FC）等内部管理帧，不进事务层
LTSSM
Link Training and Status State Machine，链路训练状态机：Detect→Polling→Config→L0 及低功耗支线
TS1 / TS2
Training Set，训练有序集：携带链路/lane 号、速率能力、均衡请求，Polling/Configuration 阶段的"对话用语"
ASPM
Active State Power Management，链路动态电源管理：L0s 浅睡与 L1 深睡
BAR
Base Address Register：设备声明"我要多大、什么类型"的地址窗口，枚举时被写上基址
ECAM
Enhanced Configuration Access Mechanism：把配置空间映射进 MMIO 的现代访问方式（总线<20|设备<15|功能<12）
MPS / MRRS
Max Payload Size / Max Read Request Size：单包载荷上限与单读请求上限，可调的吞吐旋钮
TC / VC
Traffic Class / Virtual Channel：给 TLP 分服务等级的机制（音视频 vs 批量）
Bifurcation
把一条 x16 物理链路拆成 x8+x8 / x4×4 供多设备使用，需芯片组与 BIOS 支持
