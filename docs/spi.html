SERIAL PERIPHERAL INTERFACE · MOTOROLA · 1980s

SPI 四 线 全 双 工 · 嵌 入 式 世 界 的 高 速 公 路

1980 年代中期，Motorola 给 MCU 配外设时定下了这四根线：SCLK / MOSI / MISO / CS。 没有地址位、没有应答、没有帧头——每一拍时钟都在搬数据，发一个字节的同时，必然收到一个字节。 往下滚：四种采样模式怎么选、移位寄存器如何「环形交换」、以及为什么你的 Flash 读出来总是错一位。

01

它是什么，为什么需要它

What & Why

一句话：SPI 是一种「用引脚换速度」的同步串行总线——不要地址、不要应答、不要上拉，时钟一响数据就流，快得理直气壮，也裸得一丝不挂。

SPI（Serial Peripheral Interface）由 Motorola 在 1980 年代中期随 MC68HCXX 系列定义， 四根信号线：SCLK（主机时钟）、MOSI（主出从入）、 MISO（从出主入）、CS（片选，低有效）。 主机把要发的字节装进移位寄存器，时钟每走一个沿，MOSI 与 MISO 各挪一位——8 拍之后，两个字节完成交换。

定位对比：I²C 用两根线 + 7 位地址 + 应答位，省引脚但每字节都要「点名」； UART 连时钟都没有，靠双方各自数拍子（波特率），只能点对点。 SPI 的哲学完全相反：每个从机专门一根片选、数据有去有回两条道， 于是没有寻址开销、没有上拉 RC 限制——几十 MHz 是家常便饭，QSPI 存储接口能到 200 MHz 级。

谁在用：NOR Flash（W25Q / XT25）、TFT/OLED 屏（ST7789、ILI9341）、 ADC/DAC（AD7606、MCP3208）、SD 卡的 SPI 兼容模式（见 SDIO 页）、 以太网控制器（W5500、ENC28J60）、射频模块（nRF24L01、SX1278）、CAN 控制器（MCP2515，见 CAN 页）—— 嵌入式世界里「一切稍微需要点带宽的外设」的默认接口。

FACT / A

四根线各司其职 SCLK·MOSI·MISO·CS

一根时钟、两条方向相反的数据道、一根「点名」线。CS 拉低 = 选中并复位该从机的位流状态机；拉高 = 本轮事务结束。

FACT / B

没有协议栈：裸位流

无地址位、无应答、无 CRC、无帧头帧尾——每个时钟沿都在搬数据。快是快了，出错只能靠上层自己发现（对比 I²C 的 ACK / SDIO 的 CRC7）。

FACT / C

全双工的本质：环形交换

主从各有一个 8-bit 移位寄存器首尾相接成环。想「只发不收」做不到——04 节把这个环拆开给你看：发 dummy 字节就是在「付时钟税」。

FACT / D

万物皆可 SPI，但没有「标准」

规格只管电气层和四线骨架；模式（CPOL/CPHA）、位序、命令集全由器件手册说了算。读手册的时序图，是 SPI 工程师的基本功。

02

物理层：推挽、片选与多从机拓扑

Physical Layer

SPI 的每根线都是推挽驱动、点到点布线——这四个字就是它快的全部秘密。 每张卡片里都是正在运行的实时波形（Mode 0 传输 0xA5 / 回读 0x3C）。

SCLK时钟 · 主机单向播发CLOCK

只有主机能发时钟，从机「免费」获得节拍。频率可低到 Hz 级（软件模拟）高到上百 MHz；空闲电平由 CPOL 决定，采样沿由 CPHA 决定（03 节实验室）：

f(SCLK) = f(SYS) ÷ 分频（2 / 4 / 8 …，只能取离散值）
MOSI主出从入 · SI / SDIOUT

主机推挽驱动，承载命令 / 地址 / 数据。所有从机都在「听」，但只有被 CS 选中的才会理睬。默认 MSB 先行——位序配反是经典翻车点（05 节）。

主机 TX → MOSI → 从机 RX，方向永远不变
MISO从出主入 · SO / SDOIN

被选中的从机推挽驱动，未选中的从机呈高阻——这就是多从机能共用一根 MISO 的原因。想读数据？先在 MOSI 上发 dummy 字节「买」时钟（04 节）。

读 N 字节 = 写 N 个 dummy（0x00 或 0xFF）
CS片选 · NSS / SS · 低有效SELECT

拉低 = 选中，同时复位从机内部的命令状态机；一次事务期间必须保持低。每多挂一个从机就多一根 CS——引脚换速度的「账单」在这里付。

CS 低电平期间 = 一个「事务窗口」：命令 + 地址 + 数据一气呵成

推挽 vs 开漏：速度差距的根源

PUSH-PULL vs OPEN-DRAIN
为什么 I²C 上不了几十 MHz：开漏 + 上拉的本质是 RC 充电电路，上升时间 t = 0.85·R·C；推挽两管轮流导通、主动灌拉电流，才撑得起陡峭边沿。代价：SPI 不能线与、不能多主仲裁——每根线只有一个驱动者。

04

移位寄存器：看得见的「环形交换」

Shift Ring Lab

全双工不是玄学：主从两个 8-bit 移位寄存器首尾相接成一个环，时钟每走一个沿，所有位同时挪一格。 绿色筹码是主机发出的位、琥珀色是从机发出的位——看它们如何互相穿过对方到达对岸。

时钟沿 0 / 8 等待时钟… 主机已收 0 位 · 从机已收 0 位
全双工的推论——「读」也必须写：主机不发包，时钟就不会走，从机的数据永远出不来。 所以读 Flash 时要在 MOSI 上发 dummy 字节（0x00 / 0xFF）来「付时钟税」； 写 Flash 时 MISO 上回来的垃圾直接丢弃即可。发一个字节的同时必然收到一个字节——收到的有没有用，是你的事。
05

传输要素：位序 · 延时 · 频率 · 连发

Transfer Essentials

SPI 没有统一标准，这四件事每次接新芯片都要对手册核对一遍——它们不写在协议里，写在每颗芯片的时序图里。

ORD

MSB / LSB 先行

BIT ORDER
Linux 里对应 SPI_LSB_FIRST / 设备树 spi-lsb-first；0xB4 与其镜像 0x2D 是排查位序最快的试金石——读器件 ID 一测便知。
TIM

CS 到首时钟的延时

tCSS SETUP
CS 由 GPIO 软件控制时最容易踩：拉低后立刻砸时钟，从机状态机没就位，首字节丢失。用 cs-gpios 让内核管理，或在片选后加手册要求的延时。
FMAX

时钟频率上限

CLOCK LIMIT
两个上限取小者：从机规格书的 fmax（数据手册首页时序参数）与主机控制器的分频极限。走线越长、板越差，实际可用频率越低——降速永远是第一颗药（08 节第 4 步）。
BURST

多字节连续传输

BURST / CS FRAMING
CS 低电平期间时钟可以一直走——这就是「突发传输」：命令、地址、数据在同一个窗口内连续移位，无需每字节重新片选。注意有些器件（部分 DAC / 某些 ADC）要求逐字节脉冲 CS，务必读手册。
SPI VARIANTS · 数据线复用
QSPI 与 XIP 一句话：Quad/Octal SPI 把数据线「借」来并行搬多位，配上 XIP（Execute In Place）就能把外部 Flash 直接映射进 CPU 地址空间取指执行——STM32 的 QUADSPI、i.MX 的 FlexSPI 都为此而生。

踩坑指南 · 症状 → 病因

Troubleshooting

调 SPI 的时间几乎都花在下面这些地方。按症状对号入座。

字节
移一位
读出的数据整体错位 / 偶发错字节 CPOL/CPHA 不匹配

模式配错不会不通——采样点挪了半拍，读到的位流整体移位。症状：Flash ID 读出怪值、寄存器偶发错。修法：spidev_test -O -H 四种组合轮试，读 ID 最快验证；再拿手册时序图核对采样沿。

首字节
丢失
GPIO 控 CS 时序错 tCSS 不足 / 逐字节误拉高

软件拉低 CS 后立刻砸时钟，从机状态机没就位；或传输库「贴心地」每字节自动拉高 CS，把一次事务截成多段。修法：改用硬件 CS / cs-gpios 让内核管理，或在片选后加手册要求的建立延时，检查 cs_change 语义。

MODF
模式错
模式错误标志 MODF 置位 · 传输静默失败

STM32 等控制器的 NSS 被配成输入且检测到低电平 → 硬件认为「另一个主机在占用总线」主动罢工。修法：单主系统里 NSS 设为输出（SSM=1 + SSI=1 软件从模式）或干脆复用为 GPIO；确认没有两个设备都在发 SCLK。

降速
就好
速率过高 · 信号完整性 过冲/振铃

面包板 + 杜邦线在 10 MHz 以上就是天线：数据花、CRC 错、只有降速才稳。修法：缩短走线、减少回流环路、串联 22–33 Ω 抑制振铃、降低驱动边沿；频率上限 = 从机 fmax 与走线质量的小者。

位镜像
0xB4→0x2D
MSB/LSB 配反 LSB_FIRST

主机 MSB 先行、器件却 LSB 先行（少数传感器/音频芯片）：收到的每个字节都是镜像，0xB4 变 0x2D，地址命令全部对不上。修法：查手册位序位，Linux 侧开 spi-lsb-first / SPI_LSB_FIRST。

MISO 恒
00/FF
无从机驱动 MISO 未选中 / 未使能输出

恒 0x00：线没接对或从机根本没被选中；恒 0xFF：线上拉高但无人驱动——SDO 未使能、器件还在睡眠、或命令流不对没进读态。修法：先发 dummy 字节确认在读窗口内、查 CS 是否真的拉低、查器件唤醒命令。

六条铁律

GOLDEN RULES
  • 1CS 低才说话：拉低 = 事务开始，保持低 = 连续传输，拉高 = 结束。
  • 2模式四件套：CPOL · CPHA · 位序 · 频率，两端必须逐项一致。
  • 3发一字节必收一字节：读数据就发 dummy（0x00/0xFF），别指望单向。
  • 4MSB 先行是默认：读出的字节像镜像，先查 LSB_FIRST。
  • 5频率 ≤ 从机 fmax：分频只有 2 的幂，线越长频率越低。
  • 6按方向接线：MOSI→SDI、MISO←SDO（别被 SDI/SDO 名字绕晕），共地别忘。

Execute In Place：Flash 直接映射进地址空间取指，QSPI 的招牌玩法。
MODF
Mode Fault：控制器检测到多主冲突（NSS 异常拉低）时置位并停止传输。
Push-Pull
推挽输出：上下两管轮流导通，边沿陡峭——SPI 速度的物理根基。
cs_change
内核 SPI 传输标志：控制多次传输之间 CS 是否保持拉低。
