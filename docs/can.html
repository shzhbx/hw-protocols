01

它是什么，为什么汽车需要它

What & Why

一句话：CAN 是一条「没有主机」的多主串行总线——任何节点随时可以发起通信，冲突由硬件仲裁当场解决，且不破坏任何一位数据。

上世纪 80 年代，汽车电子控制单元（ECU）数量爆炸：发动机喷油、ABS 防抱死、自动变速箱彼此都需要交换数据。 点对点连线意味着线束根数按节点数平方增长——重、贵、还不可靠。 1986 年 Robert Bosch 发布 CAN（Controller Area Network），1991 年定稿 CAN 2.0， 1993 年成为 ISO 11898 国际标准。

为什么必须「多主」？因为车里没有哪台 ECU 天生是主机：ABS 的事等不起仪表来轮询。 若设一个主机，主机宕机 = 全车通信瘫痪——安全上不可接受。CAN 的三件套把这个死结解开： 差分传输（CAN_H/CAN_L 双线，共模噪声在差分中抵消，发动机点火噪声也压不垮）； 线与电气特性（任何节点都能把总线拉成显性，谁也拦不住）； 逐位仲裁（一边发送一边回读，发现被覆盖就立即退让，赢家的帧完好无损——所以叫「非破坏性」仲裁）。

应用远不止汽车：工业自动化的 CANopen（欧洲工业主流，用对象字典 + PDO/SDO 组织数据）与 DeviceNet（罗克韦尔体系，把 CAN 包装成设备级总线）都是它的高层协议； 商用车 J1939、船舶 NMEA 2000、医疗设备、电梯、卫星（CANaerospace）都在用。 与 I²C 的多主仲裁相比，CAN 距离达 40 m@1 Mbps、抗扰强得多；与 RS-485 相比，它把仲裁与错误管理做进了控制器（详见 08 节）。

FACT / A

生于 1986 Bosch

为汽车线束减重而生；CAN 2.0B 支持扩展 29-bit 标识符。今天每辆乘用车上有 5–10 条不同速率的 CAN 总线。

FACT / B

显性吃掉隐性 线与

电平逻辑与直觉相反：显性 = 逻辑 0，隐性 = 逻辑 1。多个节点同时驱动时，只要有一个 0，总线就是 0——这正是仲裁的物理基础。

FACT / C

速换距离 1M@40m

位速率与线长成反比：1 Mbps 约 40 m，125 kbps 可到 500 m，5 kbps 能跑 10 km。汽车里动力域 500 kbps、车身域 125 kbps 是经典搭配。

FACT / D

坏了会被隔离 Bus-Off

每个节点维护 TEC/REC 错误计数：超 128 进入 Error Passive（说话变小声），发送计数超 256 直接 Bus-Off 下线，防止故障节点刷屏拖垮全车。

物理层：差分、线与、120Ω 与位时序

Physical Layer

CAN 只用两根线：CAN_H 与 CAN_L。接收端看的不是绝对电平而是差压 V(CAN_H)−V(CAN_L)—— 这让它在电气噪声里稳如泰山。下面这块示波器正在回放 03 节那帧数据（ID 0x123），注意显性位时两线张开、隐性位时并拢。

CAN 的逻辑是「反」的：显性 = 逻辑 0（收发器主动驱动，差分约 2V），隐性 = 逻辑 1（松开总线，仅靠偏置电阻回到 2.5V）。总线空闲 = 一串隐性位：

0 把总线「抓住」· 1 把总线「放开」—— 多个 0 相与仍是 0
CAN_H↔CAN_L ≈ 60Ω ✓ 正确：双绞线特征阻抗约 120Ω，两端各接一个 120Ω，并联 60Ω 吸收反射。断电后用万用表量 CAN_H–CAN_L 应约 60Ω。

线与（wired-AND）是 CAN 的第二本性：收发器驱动显性像「抓住」总线，发隐性只是「松手」—— 多节点同时驱动时，只要有一个 0，总线就是 0。谁发了 1 却读回 0，谁就知道自己输掉了仲裁（04 节逐位演示这个过程）。 这也意味着任何节点都无法「堵住」总线发隐性，但一个发疯持续输出显性的节点能瘫痪全车——所以需要 06 节的 Bus-Off 隔离机制。

位时间 = 16 Tq（时间量子） 采样点 = 87.5% @500 kbps：1 Tq = 125 ns · 位时间 2 µs
✓ 采样点落在 75%–90% 区间，是 500 kbps 汽车总线的典型配置。

位时序四段：SYNC（同步段，1 Tq，负责对齐跳变沿）→ PROP（传播段，吸收线上传播+收发器延迟）→ PHASE1（相位缓冲段 1）→ 采样点 → PHASE2（相位缓冲段 2）。接收端在 PHASE1 结束处采样； 振荡器误差靠 SJW（再同步跳转宽度）伸缩 PHASE 段吸收。拖动下面三个滑杆，看采样点如何移动—— 同一总线所有节点的位速率与采样点必须一致，否则轻负载一切正常、重负载偶发出错（10 节头号暗坑）。

05

位填充 · 每 5 个同位插 1 个反码

Bit Stuffing

总线靠跳变沿维持位同步。若连续太多同值位（长串 0 或长串 1），接收端时钟会漂。 CAN 的解法：发送端每逢 5 个连续同值位，自动插入 1 个反码位；接收端计数到 5 就把下一位删掉还原。 下面输入任意十六进制字节，看填充位插在哪里——青色格子就是填充位，点右上按钮模拟接收端删除。

原始位流（SOF → 数据）· 琥珀框 = 连续 ≥5 同值的游程
线路位流（带填充位）· 青色 = 发送端自动插入的反码位
插入 0 个填充位 规则：作用于 SOF→CRC 序列；CRC 界定符 / ACK / EOF / IFS 为固定形式位，不填充；错误帧与过载帧也不填充

副作用与彩蛋：① 填充使实际帧长最多膨胀约 20%（0x000 与 0x7FF 这类「整齐」ID 最费位）；② 接收端若数到 6 个连续同值位（本该出现填充位却是同值），立即判定填充错误并发错误帧——填充规则同时是错误检测机制；③ CAN FD 的 CRC 段改用「每 4 位固定插入 1 个反码 + 填充计数器」，见 07 节。

07

CAN FD · 一帧之内换挡加速

Flexible Data-Rate

2012 年 Bosch 推出 CAN FD（Flexible Data-rate）：仲裁段维持低速保证公平裁决， 采样完 BRS 位后立刻换挡到数据速率冲完载荷，CRC 界定符前再降回来—— 载荷从 8 字节扩到 64 字节，吞吐最高提升约 8 倍。点「播放」看速率切换的走带过程。

仲裁段：所有位等宽（500 kbps）—— 仲裁与位监控必须在慢速下进行。

VS / RS-485

同样的差分线，不同的灵魂

RS-485 与 CAN 物理上像亲戚（差分双绞、多点挂载、终端电阻），但 RS-485 只定义物理层：谁先说话靠上层约定，通常是主从轮询（如 Modbus RTU over UART），没有硬件仲裁、没有内置错误管理。CAN 把仲裁、CRC、ACK、错误约束全部做进控制器——对等节点无需任何调度者。

VS / 主从总线

仲裁 vs 轮询，差在哪

主从总线的从机永远不能主动报警：传感器着火了也得等主机问到它。CAN 里任何节点随时开口，紧急帧用小 ID 天然插队——事件驱动的延迟远小于轮询周期，且不存在「主机宕机」这个单点。

Linux 实战 · SocketCAN 虚拟终端

Linux Cheat Sheet

Linux 把 CAN 抽象成网络接口（can0 / vcan0），socket 一开就能收发——没有硬件也能学：vcan 虚拟总线两分钟搭起来。 下面终端里的帧正是 03 节动画那帧 ID 0x123 · 8 字节。点击任意命令行即可复制。

vcan — 零硬件实验台
$ sudo modprobe vcan # 虚拟 CAN 内核模块
$ sudo ip link add dev vcan0 type vcan
$ sudo ip link set vcan0 up
$ ip -details link show vcan0
7: vcan0: <NOARP,UP,LOWER_UP> mtu 72 ...
vcan state Unknown ...
# 两个终端分别 candump / cansend 即可对话
真实 can0 — 起网三步
$ ip -details -s link show can0
can state ERROR-ACTIVE (berr-counter tx 0 rx 0) restart-ms 0
bitrate 500000 sample-point 0.875
$ sudo ip link set can0 type can bitrate 500000 \
sample-point 0.875 restart-ms 100
$ sudo ip link set can0 up
# restart-ms：Bus-Off 后自动 100ms 尝试恢复（必配）
candump — 总线监听
$ candump -tz vcan0 # -tz 显示相对时间戳
(0000000002.842417) vcan0 123 [8] DE AD BE EF 00 11 22 33
(0000000002.902668) vcan0 0A5 [3] 11 22 33
(0000000002.977001) vcan0 456 [2] 01 3C
$ candump vcan0,123:7FF # 只看 ID 0x123（过滤:ID:掩码）
$ canbusload can0@500000 # 实时总线负载率
can0@500000 ......... 34% load
cansend — 发帧语法
$ cansend vcan0 123#DEADBEEF
vcan0 123 [4] DE AD BE EF # ← candump 同时打印
$ cansend vcan0 123#R8 # 标准遥控帧 DLC=8
$ cansend vcan0 1F334455#0201AA# 扩展帧 29bit ID
$ cansend vcan0 123##3DEADBEEF
vcan0 123 [8] DE AD BE EF ... FD BRS # ##3 = CAN FD + BRS 加速
三个高频救命命令：① Bus-Off 自动恢复 restart-ms 100（不配的话节点掉线后永不回来）； ② canbusload 看负载率——超过 ~50% 就该分网或升 FD（对应 10 节第 4 坑）； ③ candump 的过滤语法 can0,123:7FF 在调试多节点总线时能把噪声滤掉 99%。 另：dmesg 里搜 can0 bitrate error 多半是时钟源/分频配错——对照 02 节位时序。

六条铁律

  • 1ID 越小优先级越高——安全帧给小 ID，全网 ID 必须唯一
  • 2两端各 120Ω，中间节点不接；量 CAN_H–CAN_L ≈ 60Ω
  • 3显性 0 吃隐性 1——逻辑与直觉相反，读波形先想线与
  • 4位速率 + 采样点全网一致（500k@87.5% 是默认审美）
  • 5配 restart-ms——否则 Bus-Off 后节点永不自愈
  • 6负载率 > 50% 就动手——低 ID 流量会饿死高 ID 帧

术语表

显性 / 隐性 Dominant / Recessive
逻辑 0 / 逻辑 1。显性主动驱动（差压≈2V），隐性松开靠偏置（≈0V）；显性覆盖隐性。
线与 Wired-AND
多节点同时驱动时总线电平按「与」合成：只要有一个显性 0，总线即显性——仲裁的物理基础。
仲裁 Arbitration
SOF+ID 阶段逐位「发-读-比」：发隐性读回显性者立即退让，ID 小者胜，帧不受损。
位填充 Bit Stuffing
发送端每 5 个连续同值位插入 1 个反码位，保住跳变沿供时钟同步；接收端删除。
采样点 Sample Point
位时间内读取电平的时刻（PHASE1 末尾），全网必须一致；500k 惯例 87.5%。
TEC / REC
发送/接收错误计数器。出错累加、成功递减，驱动 Error Active → Passive → Bus-Off 状态机。
Bus-Off
TEC>255 后节点下线；监测到 128 次 11 个连续隐性位方可清零复位（Linux 用 restart-ms 自动做）。
BRS / ESI
CAN FD 控制位：BRS=1 时采样点后切换到数据速率；ESI 指示发送节点处于 Error Passive。
SRR / EOF / IFS
扩展帧替代 RTR 的隐性位（保证让位于同号标准帧）；帧结束 7 隐性位 + 帧间空间 3 隐性位。
J1939 / OBD-II / CANopen
商用车应用层（29bit ID）；乘用车诊断（0x7xx + ISO-TP）；欧洲工业主流高层协议（对象字典 + PDO/SDO）。
