TDM 一 条 数 据 线 · 16 路 音 频 · 时 分 复 用

智能音箱里 8 个麦克风、回声消除参考、扬声器回采——全都挤在同一根 DATA 线上排成一列纵队。 这就是 TDM：把 I²S 的「左右两个声道」 推广成「N 个时隙」，让一条同步串行总线承载整支音频部队。往下滚动，亲手切换帧同步格式、分配时隙、算出 BCLK。

01

它是什么，为什么需要它

What & Why

一句话：TDM 就是「多声道版 I²S」——帧同步脉冲标记帧头，一帧里的 N 个时隙（slot）依次承载 N 路音频采样，一条数据线按时分复用跑完全部通道。

TDM（Time-Division Multiplexing，时分复用）在音频语境下常与 PCM 接口混称： PCM 是「采样值原样串行传输」的编码方式（见 I²S 页 01 节）， 而 PCM-TDM 指的是把一帧 PCM 拆成 N 个时隙轮流传的总线形态。 它的血统来自电信：E1 载波把 2.048 Mbps 切成 32 个 64 kbps 时隙跑 30 路电话—— 今天 16kHz×8 槽×16bit 的麦克风阵列总线，BCLK 恰好也是 2.048 MHz，历史在这个频率上转了个圈。

与 I²S 的关系一句话讲透：I²S 是 slots=2 的 TDM 特例。I²S 用 50% 占空的 LRCLK 把一帧劈成左右两半； TDM 把 LRCLK 换成一个窄窄的 FSYNC 脉冲（或保持 LRCLK 形状但每半帧塞多个槽）， 脉冲之后 2/4/8/16 个时隙鱼贯而出。硬件完全同构：还是 BCLK + 帧时钟 + DATA 那三根线， 所以几乎所有 I²S 控制器（SAI、McASP、McBSP、ESP32 I2S）都「顺便」支持 TDM。

为什么需要它？8 个麦克风各拉一对 I²S 线是灾难；模拟混音又丢精度还吃地噪声。 TDM 的答案：多路采样共享一条线、一个时钟，零协议开销、确定性延迟—— 每一帧里每路音频都有固定位置，接收端按槽号「对号入座」即可解复用， 回声消除的参考信号和麦克风信号天然采样级对齐，这是 AEC 算法能收敛的前提。

USE CASE / A

多麦克风阵列 8-mic

智能音箱 / 会议设备的 4–8 个数字麦并成一路 TDM 送给 DSP 做波束成形与远场唤醒。麦阵列前端还可以是 DMIC(PDM)，由 DSP「PDM 转 TDM」后再上行。

USE CASE / B

回声消除参考信号 AEC REF

扬声器播放的远端信号（reference）与近端麦克风同帧传输：同一 FSYNC 下采样点一一对应，AEC 滤波器不用再做重采样对齐——参考信号晚一拍，回声就消不干净。

USE CASE / C

SoC 间音频总线 AP ↔ DSP

应用处理器与音频 DSP / modem / 蓝牙芯片之间用 TDM 互连：上行多路麦克风，下行多路播放，一根总线全双工（DIN/DOUT 各一根，时钟共享）。

USE CASE / D

蓝牙通话链路 HFP / SCO

通话时上行 mic + 下行参考、降噪通道编成一帧 8kHz/16kHz 的窄带 TDM（8 槽×16bit=1.024 MHz），从蓝牙 SoC 送到音频编解码器——电话时代基因的直接延续。

02

三根信号线与主从关系

Signals & Topology

TDM 的物理层与 I²S 完全同构：一根位时钟、一根帧时钟、一根（或一对）数据线。变化只在于帧时钟的含义——从「左右声道」升级为「帧头标记」。每张卡片里都是正在运行的实时波形。

BCLKSCK / BCK / 位时钟CLOCK

位时钟，每个脉冲搬一个比特，由主机连续产生。TDM 的帧更长，BCLK 也更快——slots 和位宽一多，频率轻轻松松上十兆：

f(BCLK) = fs × Nslots × Wslot
FSYNCLRCLK / WS / FR / 帧同步FRAME

TDM 里这根线不再叫「左右」，而是帧头脉冲：Short-Frame 只有 1 个 BCLK 宽，Long-Frame 盖住整个首槽，I²S 格式仍是 50% 方波。频率恒等于采样率：

f(FSYNC) = fs = f(BCLK) ÷ (N × W)
DATADIN / DOUT / SDATA · 全双工DATA

串行数据，N 路音频按槽轮转，每个采样 MSB 先行、二进制补码。通常收发各一根：DOUT（主机→从机）+ DIN（从机→主机），共享同一对时钟——比 I²S 更常见的全双工形态。

MCLKSYSCLK / 主时钟（可选）AUX

与 I²S 一样不是必需品，但 Codec 的 Δ-Σ、PLL、滤波器靠它吃饭。TDM 场景通常取整数倍关系，方便两级时钟同源分频：

f(MCLK) = 256 × fs（最常见 · 同源分频出 BCLK）

主从关系 · 谁驱动 BCLK 与 FSYNC，谁就是主机MASTER / SLAVE

Slot Allocator

TDM 的全部魔法就在这一帧里：N 个时隙 × W 比特，每个槽分配给一个声源。下面把一帧摊开， 调整槽数与位宽，给每个槽指定用途（麦克风 / 回声参考 / 播放 / 静音 / 空闲），看扫描光标如何逐槽点亮、多路数据如何轮流上线。

行话解码：TDM256 / TDM512 指的是一帧的总 BCLK 数，不是声道数—— TDM256 = 8 槽 × 32bit（48kHz 时 BCLK 恰为 12.288 MHz），TDM512 = 16 槽 × 32bit。 另外注意 槽宽 ≠ 有效位宽：24bit 音频常装在 32bit 槽里低 8 位补 0（或符号扩展），如同 I²S 页的 32 槽装 16bit 字。
05

时序参数与变体

Timing & Variants

三种格式之外，还有四个「旋钮」会让同一份音频听起来天差地别：采样沿、槽偏移、极性、MSB/LSB 顺序。逐个过一遍。

EDGE

上升沿采样 · 下降沿换数

CAPTURE RULE
主流约定与 I²S 一致：发送端在 BCLK 下降沿更新 DATA/FSYNC，接收端在上升沿锁存——边沿错开半拍，建立/保持时间天然满足。少数器件（部分 DSP 的接收口）反过来用下降沿采样，两个「上升沿采样」的设备对接就靠寄存器翻转采样沿。
OFFSET

槽偏移 · 声道错位之源

SLOT OFFSET
很多 Codec 有 slot 编号寄存器（TDM offset / slot select）：让本芯片的数据不从槽 0 起始，或把左右声道映射到任意槽。它与驱动的槽映射差一位，所有声道就整体平移一格——回声参考滑进麦克风通道、AEC 直接失效（08 节症状①）。

Linux 上的 TDM · ASoC 实战

Linux Cheat Sheet

嵌入式 Linux 的 TDM 由 ALSA / ASoC 管理：一个时隙 = 一个 ALSA 声道，机器驱动通过 snd_soc_dai_set_tdm_slot() 下发槽映射，格式由 dai_fmt（dsp_a / dsp_b）声明。 点击任意命令行即可复制。

ls — 你的 TDM 声卡在哪
$ aplay -l && arecord -l
card 1: TDMArray [tdm_mic_array], device 0
$ cat /proc/asound/cards
1 [TDMArray]: tdm_mic_array - TDM Mic Array (8ch @48k)
# 8 时隙声卡 → arecord 里就是 8 声道 PCM 设备
hw_params — 运行时验证
# 录音进行中执行（pcm0c = capture）
$ cat /proc/asound/card1/pcm0c/sub0/hw_params
status: RUNNING
format: S32_LE ← 槽宽 32（有效位可能 24/16）
rate: 48000 channels: 8
→ BCLK = 48000 × 8 × 32 = 12.288 MHz，对 06 节计算器
capture — 逐声道点检
$ arecord -D hw:1,0 -f S32_LE -r 48000 -c 8 /tmp/tdm.wav -d 5
# 拖进 Audacity 分声道查看；依次敲每个麦克风
# 敲 MIC2 却是 CH1 动 → slot offset 错一格（08 节①）
$ sox /tmp/tdm.wav -n spectrogram # 频谱复查

Machine Driver — set_tdm_slot 的标准姿势（C）
/* 机器驱动 hw_params：TDM 的内核配置入口（内核 >= 5.x） */
static int
board_hw_params(struct snd_pcm_substream *sub,
struct snd_pcm_hw_params *p)
{
struct snd_soc_pcm_runtime *rtd = sub->private_data;
struct snd_soc_dai *cpu = snd_soc_rtd_to_cpu(rtd, 0);
struct snd_soc_dai *cdc = snd_soc_rtd_to_codec(rtd, 0);
int ret;
/* tx/rx mask：每位一槽 · 0x00FF = 启用槽 0..7 */
ret = snd_soc_dai_set_tdm_slot(cpu, 0x00FF, 0x00FF, 8, 32);
if (ret < 0) return ret;
/* CPU DAI 与 Codec DAI 两侧都要设，且参数一致 */
return snd_soc_dai_set_tdm_slot(cdc, 0x00FF, 0x00FF, 8, 32);
}
static const struct snd_soc_ops board_ops = { .hw_params = board_hw_params };
/* dai_link.dai_fmt = SND_SOC_DAIFMT_DSP_A | SND_SOC_DAIFMT_CBS_CFS | … ←→ 格式×主从，见 03/05 节 */
DTS — simple-audio-card + tdm-slot 属性
/* 声卡：SoC SAI/I2S 控制器（主机）+ TDM Codec（从机）*/
sound
{
compatible = "simple-audio-card";
simple-audio-card,name = "TDM-Array";
simple-audio-card,format = "dsp_a"; /* ←→ 03 节 Short-Frame·延迟 1 BCLK */
simple-audio-card,bitclock-master = <&sai1>; /* 谁出 BCLK 谁是主机 ←→ 02 节 */
simple-audio-card,frame-master = <&sai1>;
simple-audio-card,cpu { sound-dai = <&sai1>; };
simple-audio-card,codec { sound-dai = <&codec0>; };
};
&sai1
{ status = "okay"; assigned-clock-rates = <12288000>; }; /* BCLK=48k×8×32 */
/* Codec 侧：set_tdm_slot 的设备树写法（由驱动 snd_soc_of_parse_tdm_slot 解析）*/
&codec0
{
dai-tdm-slot-num = <8>; /* slots */
dai-tdm-slot-width = <32>; /* slot_width */
};
ASoC 四要点：① dsp_a（+1 BCLK）与 dsp_b（0 延迟）对应 03 节两种 PCM 帧，错一个 bit 就是满噪声； ② set_tdm_slot() 的 tx/rx mask 是槽使能位图，某位没开，那个声道永远静音； ③ 槽宽 32 ≠ 有效位 32——ALSA 的 S32_LE 常只是容器； ④ 两块芯片的 TDM 参数（槽数/槽宽/格式/主从）必须完全互为镜像，任何一处单边修改都会让整条总线失步。

踩坑指南 · 症状 → 病因

Troubleshooting

调 TDM 的时间几乎都花在下面这些地方。按症状对号入座，每条都给出验证手段。

声道
错位
Slot offset / 槽映射错一格 · 全部声道平移

Codec 的槽编号寄存器（TDM offset）与驱动映射差一，或 mask 中空槽没剔除导致后槽前移。症状：敲 MIC2 时 CH1 有波形、AEC 参考滑进麦克风通道。验证：逐个敲麦看 Audacity 哪个声道动；核对 dai-tdm-slot-num 与 codec 的 slot-map 寄存器。

左右
互换
LRCLK 极性反 / I²S 格式声道序对调

TDM2/TDM4 跑 I²S 格式时，双方对「低=左还是低=slot0」理解相反，或 WS 极性（NF/PF）配置不同。症状：立体声镜像、多声道两两换位。查 dai_fmt 的帧极性位与 codec 的 polarity 寄存器，两边取反要同步。

数据
截断
BCLK 不够快 · 尾部时隙被腰斩

BCLK 实际频率 < fs×N×W（分频比取整误差、时钟树给错），一帧装不下全部槽：靠后的声道丢样或满幅削顶。验证：示波器量 BCLK 对 06 节公式；检查 assigned-clock-rates 能否精确整除，必要时改用 256/384×fs 同源分频。

沙沙
白噪
dsp_a 与 dsp_b 差 1 个 BCLK

帧同步格式两端不一致，采样窗整体偏 1 bit，MSB 被当中间位采走——满带白噪、幅度异常。在 03 节切换两种格式看清差异，然后统一两端的 format 寄存器 / dai_fmt。MSB/LSB 顺序错配是同类症状的孪生兄弟。

单道
恒零
mask 位没开 · 或槽被静音/占空

tx/rx mask 某位为 0，或 codec 端该槽 muted，也可能两个从机抢了同一个槽互相抵消。症状：个别声道永远安静而其余正常。先 dmesg 看 slot_mask，再查 codec 槽占用表——共享总线上槽号必须唯一（02 节拓扑 C）。

周期

FSYNC 与 BCLK 不同源 / 非整数倍

FSYNC 边沿没对齐 BCLK、或 BCLK 不是 N×W 的整数倍，捕获点逐帧漂移，每帧边界产生一次冲击噪声。让 BCLK 与 FSYNC 出自同一 PLL，帧长精确等于 N×W 个 BCLK；示波器单次触发看 FSYNC 上升沿是否压在 BCLK 边沿上。

空闲槽不置零 · 槽宽不一致

未使用的槽带着上一次的残留数据上路，或两端槽宽（16 vs 32）不一致导致声道占用错位的 bit 区间。显式把空闲槽清零或禁用（mask），并确认两侧 slot_width 完全相同——04 节分配器里 MUTE 槽平直为 0 就是正确姿势。

CHEAT / 公式

时钟三连 fs→BCLK

BCLK = fs × N × W　·　FSYNC = fs　·　MCLK = 256×fs（可选）　·　槽时长 = W ÷ BCLK　·　I²S = N 为 2 的特例（fs×W×2）。

CHEAT / 时序铁律

沿与捕获点 EDGE

Tx 在 BCLK 下降沿换数，Rx 在上升沿采样。Short-Frame：CH1 MSB = FSYNC↑ 后第 2 个上升沿；Long-Frame：第 1 个；I²S 格式：沿后延迟 1 BCLK。

CHEAT / 内核

ASoC 接口 set_tdm_slot

snd_soc_dai_set_tdm_slot(dai, tx_mask, rx_mask, slots, slot_width)；dai_fmt = DSP_A / DSP_B × 主从位；DTS 用 dai-tdm-slot-num / dai-tdm-slot-width；CPU 与 Codec 两侧都要设。

CHEAT / 排障

四步定位 DEBUG

① 示波器量 BCLK 频率对公式 → ② 看 FSYNC 宽度与延迟对格式 → ③ 录 N 声道逐个敲麦看错位 → ④ 核 mask 与 slot offset。90% 的 TDM 问题死在第③步。
