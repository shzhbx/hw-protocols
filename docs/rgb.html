01

它是什么，为什么引脚多还流行

What & Why

一句话：并口 RGB 是 SoC 与屏幕之间最原始的通道——PCLK 打拍子，HSYNC/VSYNC/DE 划界，24 根线并行送出像素，时序对上屏就亮。

RGB 接口（parallel RGB，也叫 RGB LCD）是 SoC 的 LCD 控制器与 TFT 面板之间的并行像素总线： 一根 PCLK 每拍送一个像素，HSYNC 每行发一个脉冲、VSYNC 每帧发一个脉冲， DE 标注"当前像素有效"，R[7:0] G[7:0] B[7:0] 24 根数据线承载颜色。 没有命令、没有包、没有校验——控制器从显存逐像素取出数据摊在时间轴上，面板照单全收。

这套时序词汇直接继承自 CRT 时代的 VGA：HSA/HBP/HFP、VSA/VBP/VFP 这些 porch（消隐）参数 与 1987 年的 VGA 显示器一脉相承。今天的 STM32 LTDC、NXP eLCDIF、全志/Rockchip 的 LCDC， 造的都是同一种波形；3D 打印机、示波器、HMI 工控屏、收银副屏，以及开发板上最常见的 4.3/5/7 寸 800×480、1024×600 屏，八成就是并口 RGB。

为什么 28 根引脚还流行？因为每根线都是"哑"信号：无 PHY、无协议栈、无枚举，寄存器配好时序就能跑； 延迟确定（一帧内直达屏幕），FPGA/CPLV 也能直推，面板侧源极驱动器天生吃并行数据。 代价是 PCB 要挤 20–28 根尽量等长的线、连接器又大又贵——所以 10 寸以上普遍换 LVDS / MIPI DSI（§10）。

注意区分：常说的 "MCU 屏"（8080 并口 + GRAM，如 ILI9341）不是 RGB 屏——前者显存做在屏里、用并口写命令； RGB 屏没有 GRAM，必须持续刷新，刷新一停画面就消失。另外 RGB 屏上电时仍需要一根 SPI 或 I²C 旁路发初始化命令（§08）。

FACT / A

生于 VGA 时序 porch

消隐期概念源自 CRT 电子束"飞回"（retrace）需要的时间。LCD 没有电子束，但整套 HSA/HBP/HFP、VSA/VBP/VFP 参数被原样继承，成为所有显示接口的通用词汇。

FACT / B

一拍一个像素 PCLK

PCLK 频率 = 总像素数 × 帧率，与数据线宽度无关。640×480@60 只要 25.175 MHz——STM32F429 的 LTDC、i.MX6UL 的 eLCDIF 都轻松跑满。

FACT / C

无协议栈但有旁路 SPI/I²C

RGB 线上跑的永远是像素，但面板驱动 IC 上电时要先用 SPI/I²C 写初始化命令（gamma、扫描方向、DISPON……），这段流程错了，RGB 再标准也黑屏。

FACT / D

频率天花板 ~85 MHz

并口在 50–85 MHz 后，24 根线的偏斜（skew）、串扰、EMI 全面失控。1080p60 要 148.5 MHz——这就是笔记本屏转投 LVDS、手机屏转投 MIPI DSI 的直接原因。

02

信号图解 · 28 根线的拓扑

Signals & Topology

RGB888 = 4 根控制 + 24 根数据。先看拓扑：谁驱动谁、往哪流；再看每张卡片里正在运行的实时波形。

▲ 4 控制线 + 3×8 数据线 = 28 根（RGB888）；RGB666 面板只接 18 根数据线（§06），RGB565 只需 16 根。

PCLK像素时钟 / Dot ClockCLOCK

全局节拍器：一个周期 = 一个像素，面板在选定边沿（可配上升/下降）同时锁存 DE 与 24 根数据线。频率由分辨率与帧率决定，不是想跑多快就多快——面板有上限：

f(PCLK) = Htotal × Vtotal × 帧率（§07 计算器）
HSYNC / VSYNC行 / 帧同步SYNC

HSYNC 每行一个脉冲宣告"新行开始"，VSYNC 每帧一个脉冲宣告"新帧开始"。宽度（HSA/VSA，单位是像素/行）与极性都可配，多数面板低有效；DE 模式下部分面板甚至不接这两根线（§05）：

一帧 = 525 行（480 可见 + 45 消隐）· 一行 = 800 PCLK
DEData Enable · 数据使能ENABLE

高电平 = "这个 PCLK 上的像素有效"。面板不再自己数时钟找行首，DE=1 就收、=0 就丢——对 PCLK 抖动与丢拍免疫，因此成为现代面板的主流约定（§05 详细对比）：

DE 高电平宽度 = 一行的可见像素数（640）
R[7:0] G[7:0] B[7:0]24 位并行像素总线DATA

24 根线并行承载当前像素颜色，每个 PCLK 更新一次。上图色块就是线上的真实值——上半是彩条、下半渐变，正是 03 节那张测试图的缩影。走线要求组内等长，频率高了还要串阻：

24 线并行 × 25.175 MHz ≈ 604 Mbps 原始数据率

05

SYNC 模式 vs DE 模式

Sync-Only vs DE Mode

同一条线，两种约定：SYNC 模式面板在同步沿之后自己数 HSA+HBP 个时钟找第一个有效像素； DE 模式由控制器直接用 DE 标注。切换对比，顺便记住同步极性。

HSYNC/VSYNC 低有效 · DE 高有效
信号常见极性 / 沿说明
HSYNC 极性低有效（多数，可配）STM32 LTDC 在 GCR.HSPOL 配；面板手册会写 L 或 H。
VSYNC 极性低有效（多数，可配）同上 VSPOL。极性配反通常表现为画面上下/左右翻或不同步。
DE 极性高有效（几乎无例外）极少数面板 DE 低有效——务必查手册。
PCLK 采样沿上升 / 下降（可配）决定数据在哪个沿被锁存；配错一行全花（§09）。
VGA 彩蛋极性编码分辨率CRT 时代靠 HSYNC/VSYNC 极性组合区分模式：640×480=负/负，800×600=正/正，1024×768=负/正……
DE 模式为什么成为主流： ① 面板不数时钟——对 PCLK 抖动、丢拍、频率微调免疫；② porch 只需"面板能接受"，不必逐像素精确； ③ 控制器与面板两侧的时序发生器都更简单。SYNC 模式仍见于老面板与部分工控屏；很多面板两种都支持，但 DE 必接。
致命细节：同一块屏 SYNC / DE 都能亮 ≠ 配置都对。SYNC 模式下 porch 错 1 个时钟，画面就偏移 1 像素甚至整行错位； DE 模式下这 1 个时钟的误差根本不存在。调偏移问题（§09）时，先确认面板到底在哪种模式下工作。
06

像素格式 · 位宽与打包

Pixel Formats

同一根并口总线，位宽可以砍：RGB888 全血 24 根，RGB666 是面板侧最常见的 18 根， RGB565 省 8 根线且显存减半——代价是颜色数从 1670 万掉到 6.5 万，渐变开始出现色带（banding）。

888

RGB888 · 全位宽

24 WIRES
每通道 8 位、共 24 根数据线（信号总计 28 根）。显存通常按 24/32 bpp 存储再由控制器搬上线，是唯一"所见即所得"的格式。
666

RGB666 · 面板常客

18 WIRES
每通道 6 位、共 18 根线（信号总计 22 根）。SoC 侧输出 888 时接高 6 位、悬空低 2 位（虚线格）——廉价 4.3–7 寸屏的主力位宽。
565

RGB565 · 显存友好

16 WIRES
R5·G6·B5 共 16 根线，帧缓冲正好 2 字节/像素（省 1/3 显存与带宽），低分辨率 UI 常用；注意字节序/字节交换位配错会"红蓝互换"。
同一渐变 → 色带肉眼可见

▲ 位宽砍半 = 硬丢低位：渐变从连续变成一条条"色带"。dithering（空间/时间抖动）让邻近像素在两个色阶间取舍，眼睛平均出中间色——面板与 SoC 一般内置，一行配置的事。

Pixel Clock Math

PCLK = 总像素 × 帧率，消隐系数由时序标准决定。1080p60 需要 148.5 MHz——这一行数字解释了并口 RGB 的疆界。

怎么读结果：≤ 33 MHz 入门 MCU 直推毫无压力；≤ 85 MHz 中高端 MCU / 轻量 SoC 可行（走线要认真）； 再往上请直接去 LVDS 或 MIPI DSI。 显存带宽是 纯读出：双缓冲翻倍，再加 UI 渲染的写入量。
08

面板上电时序 · 复位 → 初始化 → 数据 → 背光

Power-On Sequence

RGB 屏不是"通电就亮"：面板驱动 IC 要先复位，再用 SPI / I²C 收一串初始化命令，然后 SoC 才开 RGB 数据流，最后点亮背光。点击任一步骤，时序条跳到该阶段。

时间轴非等比（µs–ms 级事件被拉开示意）
顺序错了会怎样：背光先亮 → 用户看到一瞬白屏/花屏；复位没做完就发命令 → 初始化丢失、永久黑屏； 初始化命令没发 DISPON → 数据流再正常也不显示。上电脚本请从面板厂商的参考代码抄，不要自己发明。

调试链 与 症状 → 病因表

Debug Flow

别乱试参数——按证据推进：六步调试链从最便宜的检查开始；点每一步看具体操作。症状对号入座在下面。

黑屏
背光不亮
电源 / 背光链路没通

查 BL_EN 电平、PWM 占空比、升压电路与 LED 电压。背光都不亮就别怪时序——先用 §08 第 5 步的思路把背光单独点亮。

黑屏
背光亮
PCLK / DE 没到，或初始化没跑

示波器量 PCLK：应有稳定频率（§07 算的值）。有 PCLK 再量 DE 与 RGB；都正常仍黑屏 → 抓 SPI/I²C 确认初始化命令发出且顺序正确（§08）。

画面
偏移/环绕
porch 参数配错

右移/下移 = HBP/VBP 偏大或偏小；整幅环绕 = porch 值越界。对照面板手册逐项填，别抄别的屏的参数——§04 的表就是给你对着填的。

花屏
雪花噪点
PCLK 相位 / 驱动能力 / 走线

先把 PCLK 降一半复测：错误消失 → 信号完整性问题（等长、串阻 22–33 Ω、参考地）；仍花 → 查 PCLK 采样沿与 DE 极性配置位。

闪烁
撕裂
刷新不同步 / 双缓冲没按 VSYNC 翻

渲染帧率与扫描帧率不同步：撕裂发生在帧缓冲被改到一半时。解法是双缓冲 + 在 VSYNC 时机 page flip；部分面板有 TE 输出可帮忙对齐。

红蓝
互换/偏色
颜色顺序 / 位宽映射错

纯红图显示成蓝 → RGB/BGR 顺序位没配或 R、B 总线接反；偏色断层 → 888 源打到 666 面板没丢对低位、或 565 打包字节序错（§06）。
