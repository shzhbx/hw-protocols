01

它是什么，为什么是它

What & Why

一句话：CSI-2 是 MIPI 联盟定义的摄像头串行接口——把一帧图像拆成带校验的包，经 1–4 对差分线从 sensor 单向灌进 SoC；配置面反向交给一条 I²C。

手机后摄、笔记本摄像头、行车记录仪、树莓派 Camera Module——几乎所有 CMOS 摄像头 → SoC 的链路都是 MIPI CSI-2（Camera Serial Interface，2005 年首版）。sensor 侧把像素按行打成包、经 D-PHY 串行化送出；SoC 侧接收器解包、校验、按行重组成帧，交给 ISP。

为什么不用老的 DVP 并口？1080p@30 RAW10 是约 78 MB/s 的像素流：DVP 需要 11 根以上单端线 在 60+ MHz 上同时翻转，EMI、串扰、等长布线全是灾难；CSI-2 用 2 对差分线（CLK+DATA） 就能跑 1 Gbps，4 对可到 10 Gbps——引脚省一半以上，还能折叠着过 FPC 转轴。

它与屏幕接口 MIPI DSI 是一对反向兄弟：DSI 把像素从 SoC 推给屏， CSI-2 把像素从 sensor 收进 SoC。两者共用同一套 D-PHY 物理层——LP/HS 双模式、 SoT 同步码、ULPS 低功耗态一模一样，很多 SoC 的 PHY IP 甚至同源。 D-PHY 的电气细节本页不重复，在 DSI 页有完整拆解（若想看并行 RGB 老 接口长什么样，见 RGB 页）。

FACT / A

单向高速 + 双向低速 CSI-2 + CCI

数据面永远 sensor → SoC 单向；配置面是 MIPI CCI——本质就是 I²C（100/400 kHz），曝光、增益、PLL、MIPI 时序参数全靠它写 sensor 寄存器。

FACT / B

一切皆包 PACKET

一帧 = Frame Start 短包 + 若干行长包（PH：DI+WC+ECC；PF：CRC16）+ Frame End 短包。数据与控制统一为包格式——§04 逐字段拆给你看。

FACT / C

DSI 的反向兄弟 D-PHY

与 DSI 共用物理层：LP（1.2 V 慢速）↔ HS（~200 mV 高速突发），SoT 同步码 0x1D。电气与 LP/HS 细节见 DSI 页，本页专注相机协议侧。

FACT / D

两个维度都能扩 1/2/4 lane · VC×4

数据 lane 1/2/4 条，字节轮转分发（§06）；包头里还有 2-bit 虚拟通道，一条物理总线能承载最多 4 路独立图像流（§07）。

Lane 分发动画 · 字节流的分与合

Lane Distribution

多 lane 不是"每条 lane 传半张图"，而是字节级轮转（round-robin）：B0→lane0、B1→lane1、B2→lane2、B3→lane3、B4→lane0 … 接收端按同样顺序取回，字节流完全复原。切 4/2/1 lane，看同一串字节怎么走不同的路——字节颜色 = 它在原始流里的位置（mod 4）。

SoT = 每条 lane 各自的同步头 00011101
为什么断一条 lane = 条纹花屏：lane 断开后，属于它的每 4 个字节就坏 1 个（i mod 4 全中）， 字节流周期性缺损——ISP 端表现为规律条纹。这也是调试时"条纹 = 查 lane"的由来（§09 有模拟）。另有 lane 映射与极性两个孪生坑：D0-D3 接错顺序或 P/N 反，症状与断 lane 几乎一样。

STEP 1上电时序

DOVDD → DVDD → AVDD 依次上电（XCLR 保持低），随后 XCLR 拉高、XCLK 起振，等 5–10 ms 让 sensor 内部 boot 完成——然后 CCI 才可访问。第一件事：I²C 读 CHIP ID 寄存器，确认地址与供电都对（ID 都读不到，别谈 MIPI）。上电曲线见 §02 第四张卡。

STEP 2CCI 配置链（I²C）

按 datasheet 的推荐寄存器序列走：PLL/时钟树 → mipi_clk 分频 → 曝光/增益 → 帧率(HTS/VTS) → MIPI 时序 → stream on。曝光与帧率强耦合：帧率 = PIXCLK ÷ (HTS × VTS)，曝光行数 > VTS 会被强制拉低帧率。I²C 时序/调试工具见 I²C 页。

STEP 3MIPI 时序三件事

① mipi_clk：两端 PHY 的 lane 速率档位要都能覆盖（用左侧计算器核对）；② settle time：接收端的 HS-SETTLE 采样窗口必须罩住 sensor 的 T_HS_PREPARE + T_HS_ZERO——窗口错位是"无图"第一病因；③ LP 逃逸：帧与帧之间 lane 停在 LP-11 省电，长空闲可进 ULPS，回来要重新 SoT。

形态 A单 sensor 直连

1–4 lane 差分 + CCI，最常见。树莓派 CM4 / IMX219、STM32MP1 + OV5640 都是这套。lane 数由 sensor 引脚决定，很多 sensor 2-lane 可配成 4-lane 输出减半速率。

形态 B多摄聚合 · VC 复用

手机多摄经 聚合器/桥接芯片（如 Sony CSA、虚谷桥）把 2–4 个 sensor 打上不同 VC 挤进同一条 CSI 总线——对应 §07 的时隙图。带宽是所有 VC 之和，务必用左侧计算器相加后再核 PHY 能力。

形态 CSoC 侧 · CSI RX 控制器

设备树三件套：lane 数（data-lanes = <1 2 3 4>）、lane 映射/极性（物理顺序 ≠ 逻辑顺序的重灾区）、settle（mipi-in,hs-settle 等属性，单位按平台 ns/clk）。RK/Allwinner/NXP 各家名字不同，调"无图"时永远第一个回来看它。

八条铁律
  • 1数据单向，控制反向：CSI-2 管 sensor→SoC，CCI(I²C) 管 SoC→sensor
  • 2一切皆包：FS 短包开场 → 每行一个长包 → FE 短包收场
  • 3PH = DI+WC+ECC：ECC 汉明码可纠 1 位——报头必须保住
  • 4PF = CRC16-CCITT：只检错；CRC 失败丢整行 → 图像撕一行
  • 5行长 = WC：必须等于 宽×Bpp，否则逐行错位"斜切"
  • 6lane 是字节轮转：B_i 走 lane (i mod N)，断一根 = 每 N 字节坏一个
  • 7VC 在 DI[7:6]：一条总线 4 路流，接收端只认这 2 bit 分拣
  • 8settle 罩住 SoT：HS-SETTLE 窗口错位 = 无图，调不出先查它

WC · Word Count

ECC
8-bit 汉明校验，覆盖 PH 的 24 bit，可检测 2 位、纠正 1 位错误
PF · CRC
Packet Footer：payload 的 16-bit CRC-CCITT（0x1021，初值 0xFFFF）
CCI
Camera Control Interface = 缩水 I²C：读 ID、配曝光/增益/帧率/MIPI 时序、开关流
settle time
接收端 HS-SETTLE 采样窗口，须罩住 sensor 的 T_HS_PREPARE + T_HS_ZERO；错位 = 无图
Bayer (RGGB)
单 sensor 覆盖滤色阵列：每像素 R/Gr/Gb/B 单分量，颜色由 ISP 去马赛克重建
