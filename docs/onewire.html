1-Wire 一 根 线 的 极 简 主 义 · 单 总 线 协 议 详 解

一根数据线，同时当供电线、时钟线和数据线用——1-Wire 把引脚节省到了哲学级别： 开漏 + 线与的总线上，每个器件出厂自带激光刻录的 64-bit 全球唯一 ID， 主机靠一根线把它们一个个"点名"。往下滚动：复位脉冲、读写时隙、Search ROM 二叉树， 全部拆到微秒刻度。

01

它是什么，为什么需要它

What & Why

一句话：1-Wire 是只用一根数据线（外加地）就能供电 + 寻址 + 通信的主从总线——开漏线与的物理哲学与 I²C 同宗，但把"省引脚"推到了极限。

1-Wire 由 Dallas Semiconductor 在 1990 年代推出（现归 ADI）。总线上只有两种角色： 一个主机（通常是 MCU 的一根 GPIO）和 N 个从机器件，全部并挂在一根 DQ 线上。没有时钟线——时间是靠微秒级的拉低时长来编码的， 所以 1-Wire 又叫"单总线"。

它的两个杀手锏：64-bit 唯一 ROM ID（8-bit 族码 + 48-bit 序列号 + 8-bit CRC8， 出厂激光刻录，全球不重复）与寄生供电（parasite power）——器件从 DQ 线上"偷电" 存进内部电容，连 VDD 引脚都可以省掉。于是测温探头只需两根线就能拉几十米， iButton 甚至做成一颗纽扣电池的形状。

代价同样清晰：标准速度只有 ≈16.3 kbit/s；时序刻到微秒， 软件位锤（bit-bang）期间常常要关中断；多器件枚举要自己实现 Search ROM 二叉树算法（06 节逐位演示）。它不适合搬数据， 只适合"低频、低成本、接线极简"的传感与身份识别场景。

02

物理层：开漏、上拉与寄生供电

Physical Layer

1-Wire 的全部电气规则一句话讲完：只准拉低、不准驱高，高电平交给上拉电阻。 与 I²C 的开漏线与完全同源（I²C 页有可点击的线与实验台）—— 区别是 1-Wire 连时钟线也省了，而且要把这根线当电源用。

上拉电阻取值权衡 · 拖动滑杆实时算
总线电容 CbDEVICE 20pF + 线缆320pF
时间常数 ττ = Rp × Cb1.50µs
上升到 2.2V 耗时t = −τ·ln(1−2.2/3.3)1.65µs
低电平灌电流3.3V ÷ Rp（器件极限 4mA）0.70mA
判读VERDICT标准速度充裕

权衡：Rp 小 → 上升快但灌电流大、空闲功耗高；Rp 大 → 省电但写 1/读 1 时线"爬"不回高电平。经验值 4.7 kΩ，长线/多器件降到 2.2 kΩ，Overdrive 必须更狠。

为什么必须开漏 · 三条铁律

线与：主机与所有从机的输出都是开漏 NMOS。任何一个拉低，整根线就是低——多器件同挂不会电源对撞，从机"抢答"存在脉冲也只呈现一次低。

谁都能发言，靠时序区分：没有片选、没有地址线。复位脉冲、存在脉冲、读写时隙，全是约定好的拉低时长（03/04 节逐微秒展开）。

禁止推挽驱高：想加速上升沿？唯一合法手段是"强上拉"——用 MOS 管把上拉电阻旁路，而不是直接推挽输出，否则与拉低的从机形成对地短路。这就是右侧寄生供电动画里的 P-MOS。

总线空闲 = 高（上拉维持）；通信 = 主机发起的拉低舞蹈。一根线同时是电源、时钟与数据。

03

复位与存在脉冲 · 每次对话的开场白

Reset & Presence Pulse

1-Wire 的所有事务都从同一段"开场白"开始：主机拉低 ≥480µs 宣告"全体注意" → 释放 → 等待 15–60µs → 第一个从机拉低 60–240µs 应答（存在脉冲）。时间轴精确到微秒， 绿色是主机驱动、琥珀色是从机驱动、青色是 DQ 上的线与结果。

480µs 这个夸张的时长是故意的：它必须远大于任何时隙（60–120µs），从机才能靠"低了这么久"区分出 复位脉冲与普通数据位。反过来，主机在释放后约 70µs 处采样存在位：读到低 = 总线上有活的 1-Wire 器件； 读到高 = 没人应答（切换上方"无器件"场景看看）。存在脉冲来自"第一个抢答"的从机——多个器件同时应答也只看到一撮低，这就是线与。

04

读 / 写时隙对比实验室

Read / Write Time Slot Lab

1-Wire 的灵魂在时隙：四种时隙的发起动作完全一样——主机拉低；区别只在"按多久、谁来接管"。 写 0 按住 60–120µs；写 1 与读时隙只点一下（<15µs）就松手。青色高亮 = 采样窗口： 写时隙从机在发起沿后 15–60µs 采样；读时隙主机必须在 15µs 内完成采样——晚了线就被拉回去了。

读时隙最阴险的坑：主机拉低后必须在 15µs 内读完——因为从机发 0 时会立刻接管把线按在地上， 发 1 时线已回高，晚采样读到的都是"恢复后的高"，整字节悄悄错位。软件位锤的延时务必用硬件定时器， 中断一打岔时隙就废（08 节踩坑表）。

05

ROM 命令层：总线上到底有谁

ROM Commands

每一次 1-Wire 事务都是三级火箭：复位 → ROM 命令 → 功能命令。ROM 命令解决"跟谁说话"—— 靠的就是那 64-bit 唯一 ID。

命令代码干什么什么时候用
Read ROM33h读出器件的 64-bit ID：8bit 族码 + 48bit 序列号 + 8bit CRC8总线上只有一个器件时；多器件会线与出乱码
Match ROM55h后跟 64-bit ID："接下来只跟它对话"，其余器件装死多器件总线上点名单个器件读数据
Skip ROMCCh"全体听令，不用报 ID"，跳过寻址层单器件省流程；或对所有 DS18B20同时发 Convert T
Search ROMF0h逐位二分枚举出总线上所有 64-bit ID上电枚举；Linux 内核 w1 核心自动干这事 → 下一节逐位演示
Alarm SearchECh同 Search ROM，但只有置了报警标志的器件应答DS18B20 温度越限（TH/TL）后被点名

两个高频提醒：① Skip ROM 之后跟"读"类命令，多器件会同时抢答（线与成乱码）——读数据必须 Match ROM； ② 还有 Overdrive 变体（3Ch Overdrive Skip ROM / 69h Overdrive Match ROM），进入后时隙缩短约 8 倍。

06

Search ROM · 一根线上的二叉树搜索

Binary Tree Enumeration

没有 ID 就没法 Match ROM，可 ID 藏在器件里、总线上又可能挂着 N 个——鸡生蛋问题。 1-Wire 的解法优雅到极致：每一位，主机连读两拍（原码 + 反码），靠线与听出这一位上器件的分布， 再发一个方向位让不匹配的器件退场。逐位走完 64 层，就摘出一个完整 ID；回到分叉点走另一条分支，再摘下一个。

原码读数反码读数判读主机怎么办
0000 = 分叉：这一位上 0/1 分支都有器件选一个方向发 0/1，另一分支记下来待回溯
0101 = 全 0：在场器件这一位全是 0无脑跟 0
1010 = 全 1：在场器件这一位全是 1无脑跟 1
1111 = 无器件（原码反码不可能同时为 1）死分支/总线故障 —— 回溯或报错

开始：点「单步」走一位；遇到 00 分叉会停下来等你选分支——选错的分支没有器件，读完剩余位全是 11，只能回溯。本演示总线上挂着 3 个器件：DS18B20（28h）、iButton（01h）、DS2431（2Dh）。剩 56 位同理逐位读出。
二叉树 · 亮起的部分 = 已探明

为什么能枚举完？每个分叉点最多藏一个"还没被摘过的器件方向"，算法用 last_discrepancy 指针记住最深分叉处上次走了哪边， 下轮自动换边——只要总线安静，最多 N 轮就能把 N 个器件全部点名。这就是 Linux w1 核心上电后干的第一件事（09 节）。

08

踩坑指南 · 症状 → 病因

Troubleshooting

调 1-Wire 的时间几乎都花在下面这些地方。按症状对号入座。

一直
85.0℃
读到了上电默认值 · 转换没完成

三连查：① Convert T 后等够时间（12-bit 750ms）或轮询 DQ 忙标志；② 寄生供电必须强上拉（02 节动画的"弱上拉"模式就是这个死法）；③ 别在转换中途复位——复位即重来。验证：连续读两次，第一次 85℃ 第二次正常 = 典型时序病。

上拉
太弱
写 1 / 读 1 偶发失败 · Rp 或线缆电容问题

上升沿爬不回高电平：示波器看 DQ 上升沿是不是"圆弧"。用 02 节计算器核 τ=Rp·Cb，超过 ~15µs 必翻车。处方：Rp 降到 2.2k、缩短线缆、减少分支器件数。

长线
反射
线一长错误率飙升 · 信号完整性

>10m 后振铃与反射叠加在时隙上，采样点正好踩在过冲里。处方：用双绞线（DQ+GND 一对）、坚决避免星型分叉与长 stub、总线走"手拉手"链型；必要时牺牲速度感——标准速度已是最慢档，别用 Overdrive 跑长线。

搜索
死循环
Search ROM 永不收敛 · 枚举数量翻倍/为 0

干扰把某个 01/10 读成 00（假分叉），回溯指针被带偏，循环永远走不完。处方：先解决上拉/反射问题；驱动侧核对 last_discrepancy 边界条件（标准 AN937 实现）；上电后延时 ~1s 再搜，等器件电充足。

偶发
位翻转
时隙被中断拉长 · 软件位锤的大坑

写 1 拉低应 <15µs，一个中断插进来就变成写 0，而且错得毫无规律（与负载相关）。处方：时隙期间关中断，延时用硬件定时器/DMA 而非忙等循环；或者干脆用带 1-Wire 外设的 MCU / 内核 w1-gpio。

推挽
加速
想用推挽驱高加速上升沿 · 短路风险

从机随时可能开漏拉低，主机推挽输出高 = VCC 经低阻对地放电，轻则波形打架重则烧引脚。唯一合法加速手段是 02 节的 P-MOS 强上拉——它只是"更强的上拉"，仍然是开漏体系的一部分。

3.3V
对 5V
电平域混接 · 0/1 判读漂移

5V 器件的 VIH 可能高于 3.3V 主机能给的高电平。处方：上拉统一接到主机电平域；确需 5V 器件用 MOSFET 电平移位（与 I²C 同款电路）。
