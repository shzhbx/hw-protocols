eMMC手 机 里 的 固 态 硬 盘 · 一 颗 芯 片 装 下 整 个 存 储 栈

01

它是什么，为什么需要它

What & Why

一句话：把「难伺候的 NAND 颗粒」和「懂 NAND 的主控」一起封进 BGA，对外只露一套 MMC 并行总线——主机看到的是一颗安分的块设备芯片。

eMMC（embedded MultiMediaCard）是 JEDEC 维护的标准（JESD84 系列，流行版本 4.5 → 5.1）。 一颗 eMMC 内部是三明治：NAND 颗粒（多为 TLC/QLC，几个 die）+ Flash 控制器跑 FTL 固件 （磨损均衡、垃圾回收、ECC 纠错、坏块管理、写入放大控制）+ MMC 接口 PHY。 主机永远不直接碰 NAND 的页和块——它面对的是一个 512 字节扇区的块设备，坏块代代更迭也不关主机的事。

协议层它是 SDIO 的亲兄弟：两者都继承 MMC 血统——CMD 线上永远是一问一答的 48-bit 定长命令帧（带 CRC7），DAT 线上跑带 CRC16 的数据块，R1/R1b 响应、DAT0 忙检测全部同款。 分叉在枚举入口：SD 卡用 ACMD41、SDIO 用 CMD5， 而 eMMC 用 CMD1（SEND_OP_COND）——纯 MMC 血统。把 SD 卡驱动直接拿来枚举 eMMC，注定超时。

为什么不直接挂裸 NAND？NAND 的页编程/块擦除/ECC/坏块随每代工艺全在变，主机驱动疲于奔命； eMMC 把这些全部吸进芯片内，接口十年稳定。代价是并行总线跑不远：HS400 的 200 MHz 8-bit 对走线长度极其敏感， 这也是后来串行差分的 UFS 取而代之的伏笔（05–06 节）。

FACT / A

枚举入口是 CMD1

eMMC 上电后 CMD0 复位 → CMD1 交换 OCR → CMD2 拿 CID → CMD3 分配 RCA → CMD7 选中。与 SD 卡的 ACMD41、SDIO 的 CMD5 都不同——移植驱动时的第一个坑。

FACT / B

512 字节的配置空间 EXT_CSD

速度档（HS_TIMING）、位宽（BUS_WIDTH）、分区选择、boot 配置、RPMB 大小全在这个寄存器块里：CMD8 读、CMD6 写。eMMC 的「灵魂寄存器」，09 节实战。

FACT / C

8-bit + 双沿 = HS400

DAT0-7 八根并行线在 200 MHz 下每个时钟沿各采一位：单沿（SDR）200 MB/s，双沿（DDR）400 MB/s。DDR 采样概念与 DDR 内存 一脉相承。

FACT / D

芯片里的隐藏分区 Boot×2 + RPMB

User Area 之外还有两个互为备份的 Boot 分区（放引导代码，上电可自动送出）和一块 RPMB（防回滚安全区）。Linux 里它们是 mmcblk0boot0/1 和 mmcblk0rpmb。

02

信号与总线 · 十一根线的点对点王国

Signals & Topology

CLK + CMD + DAT0-7 + RST_n，共 11 根：一根时钟、一根半双工命令线、八根并行数据、一根硬件复位。 没有地址线、没有片选——因为总线上永远只有这一颗器件（hero 图即是完整拓扑）。 HS200/HS400 时代，时钟与数据同源同向送出（source synchronous），主机靠调谐决定采样相位。

CLK时钟 · 主机单向驱动CLOCK

所有 CMD/DAT 位与它对齐。26 MHz 起步，HS200/HS400 到 200 MHz。HS200 起 CLK 与 DAT 同为源同步信号：相位按走线延迟整体平移，主机用调谐算法（CMD21）找最佳采样点。时钟一抖，8 根数据线一起完蛋：

26 MHz（DS）→ 52（HS）→ 200（HS200/HS400）· VCCQ 必须降到 1.8 V
CMD命令与响应 · 半双工COMMAND

主机的命令与芯片的响应共用一根线，永远是 48-bit 定长帧 + CRC7（R2 长响应除外）——与 SDIO 的 CMD 线完全同源。上图绿色段=主机命令（CMD17），琥珀段=芯片响应（R1）：

48 bit = 01 + 命令号×6 + 参数×32 + CRC7 + 1
DAT0-78-bit 并行 · 双向复用DATA

数据线全双向：读时芯片驱动、写时主机驱动，同一时刻只有一个方向（半双工，05 节动画演示代价）。每 512 字节块尾随 CRC16。DAT0 兼职忙线：R1b 响应后芯片把它拉低表示「写回中，别催」。HS400 时八根线全部双沿采样：

200 MHz × 8 bit × 2 沿 ÷ 8 = 400 MB/s（HS400）
RST_n / VCC·VCCQ复位 · 双电源域AUX

RST_n 拉低 ≥1 µs 硬复位（比 CMD0 干净，主控寄存器一起归零）。两个电源域：VCC 喂 NAND 核心 3.3 V；VCCQ 喂接口——HS200/HS400 必须 1.8 V。冷启动必须先 VCC 后 VCCQ 的顺序上电：

上电顺序：VCC → VCCQ → RST_n 拉高 → CMD0/CMD1 枚举

eMMC vs UFS · 半双工排队 对决 全双工乱序

eMMC vs UFS · Queue Duel

同样 8 个读写 I/O（绿色 R = 读，琥珀 W = 写），两条时间线并排跑： 上面的 eMMC CMD17/24 一条命令一件事、DAT 八根线同一时刻只能单向——读写只能排队； 下面的 UFS 读走上轨、写下轨同时流动，CQ 命令队列还让设备乱序完成（看块上的 #序号）。 这是 UFS 随机性能碾压 eMMC 的根源。

eMMC 一次一件事 · UFS 边收边发边排队HALF vs FULL DUPLEX

eMMC 的 8 根 DAT 线是共享双向总线：读的时候整条总线归芯片，写的时候整条归主机，方向切换还有死区； 命令必须完成（CMD12 停止 + R1b 忙等）才能发下一条。UFS 的每条 lane 是独立的差分收发对， 加上 32 深的命令队列，主机可以一口气塞一批命令让设备自己排最优顺序——吞吐与延迟同时赢。

06

UFS 速览 · 差分 Lane、UniPro/M-PHY、SCSI 血统

UFS Stack

UFS（Universal Flash Storage，JEDEC UFS 2.x/3.x）把「并行总线」换成「串行差分 + 分层协议栈」，用三招接过 eMMC 的班。

招式一差分 Lane · 全双工

每条 lane 是一对 差分串行线（LVDS 的远房亲戚），TX/RX 方向各自独立、互不等待。 1 lane 起步、2 lane 翻倍；UFS 2.1 双 lane 顺序读 ≈ 850 MB/s，UFS 3.1 突破 2 GB/s——并行总线到 HS400 就撞墙，差分还有大把余量。

招式二CQ 命令队列 · 乱序执行

主机一次把最多 32 个命令压进 Command Queue，设备按 NAND 内部状态自己挑顺序执行、乱序完成（05 节动画的 #序号）。 eMMC 的 CMD17/24 只能「发一个、等一个」，遇到混合读写就排队空转。CQ 的血统是 SCSI Tagged Queuing——是的，UFS 说的就是 SCSI 方言。

招式三SCSI 血统 + 安全继承

命令层直接复用 SCSI：INQUIRY、READ(10)、WRITE(10)、UNMAP（≈Trim）。RPMB 在 UFS 里也没缺席——变成一个独立的 Well-Known 逻辑单元（LU）， key + 计数器 + HMAC 的防回滚机制原样保留，Android 的防刷机验证正靠它。

07

寿命与维护 · P/E、磨损均衡、Trim 与写入放大

Endurance & Maintenance

NAND 的物理宿命：每个块只能被擦写有限次。eMMC 主控的全部智慧，就是把这件事对主机隐藏起来——但工程师必须知道账怎么算。

P/E 循环 PROGRAM / ERASE

NAND 写前必擦、擦有次数上限：SLC ≈ 10 万次、MLC ≈ 1 万、TLC ≈ 3000、QLC ≈ 1000。容量越大的颗数越多、越耐久，但每天写入量也决定生死。

磨损均衡 WEAR LEVELING

FTL 把写入摊到所有物理块，冷数据定期搬家，让各块 P/E 计数趋平——否则热点块先死，整盘报废。预留 OP 空间越多，搬得越从容。

坏块管理 BBM

出厂坏块 + 用坏块都登记进坏块表，替换到备用块。ECC（BCH/LDPC）负责纠正读错误；纠不动的块退役。这一切对主机完全透明。

Trim / 丢弃 CMD38

主机删文件后用 TRIM/DISCARD 告诉 eMMC「这些块没用了」：FTL 提前回收、减少无效搬运。不 Trim 的盘越用越慢就是这个原因——记得 fstrim 定时跑。

8-bit 起不来 · DAT4-7 没配好

三处排查：pinctrl 的 bus8 引脚组缺脚、设备树 bus-width=<8> 没写、BGA 焊接虚焊（换板验证）。ios 显示 4 bit 而 dts 写 8 → 大概率引脚复用冲突被静默降级。

RPMB
key 烧错
PROGRAM_KEY 一次定终身

RPMB 认证密钥只能烧一次，不可读、不可改：烧错/丢 key = RPMB 永久锁死，部分安全启动流程直接判废片。产线必须落盘保存 key 并先 read-counter 验证链路，再烧正式 key（03 节动画第 ① 步）。

写 boot
后变砖
掉电瞬间写 boot 分区 = 灾难

boot 分区存的是 SoC 第一级引导，写入途中掉电没有文件系统日志可救。三道保险：镜像尽量小、dd ... conv=fsync 确认落盘、双 boot 分区互为备份（坏 Boot1 还有 Boot2）。升级流程必须先写备区、校验、再切 PARTITION_CONFIG。

枚举
error -110
CMD1 无响应 · 驱动/上电顺序坑

把 SD 卡驱动（ACMD41）拿来点 eMMC 必超时——入口是 CMD1。硬件侧查上电顺序（VCC→VCCQ→RST_n）与 RST_n 是否被 GPIO 拉住。-110 是无响应、-84 是 CRC 错，先分清再动手。

越用
越慢
Trim 没跑 · GC 拖累写入放大

删文件不 Trim，FTL 以为数据还活着，GC 搬着一堆尸体跑（07 节 WA 计算器可算代价）。挂载参数加 discard 或定时 fstrim；嵌入式只读根文件系统则无所谓。慢的另一个嫌疑是过热降速——摸温度。
