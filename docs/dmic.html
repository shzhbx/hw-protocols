PDM 数 字 麦 克 风 · D M I C 协 议 详 解

两根线，请进整个麦克风阵列。PDM（脉冲密度调制）把「模数转换」直接塞进麦克风封装—— 出来的不是电压，而是密度随声压变化的 1-bit 码流。往下滚动，看声音如何被编码成一串 0 和 1。

01

它是什么，为什么需要它

What & Why

一句话：PDM 是用「1 出现的密度」表示模拟量的 1-bit 编码；DMIC 是只说这门语言的数字 MEMS 麦克风——主控给它时钟，它就吐码流，其余什么都不需要。

PDM（Pulse Density Modulation，脉冲密度调制）严格说不是「总线协议」，而是一种编码方式；DMIC （数字硅麦克风）则在芯片内部用 Δ-Σ 调制器把膜片声压直接转成 PDM 码流。手机、智能音箱、TWS 耳机里的拾音孔后面， 八成就是一颗 SPH0641 / MP34DT01 / IM69D130。

为什么不用模拟麦克风？模拟输出只有几毫伏，从麦克风走到 ADC 的一路上，电源纹波、射频干扰（旁边 Wi-Fi/BT 发射功率比它大几个数量级）全都往里灌。DMIC 把 ADC 塞进麦克风封装，出来就是数字。为什么不用 I²S？ I²S 传 16/24-bit 的 PCM，麦克风侧也要 BCK/WS/SD 三根线；PDM 只要 CLK + DATA 两根，而且两支麦克风还能共享同一根 DATA——2~8 麦的阵列布线，PDM 是成本与空间的最优解。

代价在主控侧：1-bit 密度码不能直接用，要经 ÷64 抽取滤波器（CIC/FIR）还原成常规 PCM。 好在现代 SoC（STM32 DFSDM、ESP32 PDM-RX、nRF PDM、RK/MTK PDM）都内置了这套硬件。

FACT / A

ΔΣ 调制器在麦克风里 ADC

声压→1-bit 码流的转换在麦克风芯片内部完成，出厂即标定灵敏度，主控不用碰模拟。

FACT / B

密度即幅度 DENSITY

+满幅≈全 1，0 电平≈0101 交替（50% 密度），−满幅≈全 0。「1」的密度正比于瞬时声压。

FACT / C

两线立体声 CLK+DATA

两支麦克风分别占用时钟的下降沿/上升沿驱动同一根 DATA，L/R 引脚（硬接线）决定谁用哪个沿。

FACT / D

64 抽 1 DECIMATE

fs = CLK ÷ 64：3.072 MHz 时钟 → 48 kHz PCM。抽取滤波器（CIC/FIR）是接收端标配。

02

两根信号线（+供电与配置脚）

Signals

PDM 的信号世界极其克制：一根时钟、一根数据，仅此而已。每张卡片里都是正在运行的实时波形。

CLKPDM CLK / 时钟CLOCK

主控单向驱动的时钟，麦克风完全被动——给时钟才说话，时钟一停数据口立刻高阻。每个 CLK 周期允许输出 1 个密度位，常见 1.2–3.25 MHz、占空比 45–55%：

f(CLK) = fs × 64（3.072 MHz → 48 kHz）
DATAPDM DATA / 密度码流DATA

麦克风输出：1-bit ΔΣ 密度码流。「1」的密度正比于瞬时声压；无声时是 0101 交替码型（50% 密度 = 0 电平）。立体声时两支麦克风轮流驱动这根线（03 节动画）：

密度 D = (1 + V / V_FS) / 2

04

编码原理 · 从声压到 PCM 的四级流水线

How PDM Works

1-bit 怎么可能装下 16-bit 的动态范围？答案靠两件事：过采样（64 倍冗余）和噪声整形（把量化噪声赶到听不见的高频）。

ΔΣ

Δ-Σ 调制器

MODULATOR
声压经膜片与预放大后进入环路：积分器累加「输入 − 反馈」，1-bit 量化器只判断正负，结果又经 1-bit DAC 送回输入。环路把量化误差推到高频，低频处码流密度的平均值精确跟随输入。
PDM

密度即幅度

DENSITY = AMPLITUDE
同一条码流：波峰附近「1」连成片，波谷附近「0」连成片，过零处均匀交替。注意它不是 PWM——脉冲位置被环路随机化，携带信息的只有密度，这让它对时钟抖动远不如 PWM 敏感。
÷64

抽取滤波器

DECIMATION
接收端两步走：CIC（级联积分梳状滤波）把 64 个 1-bit 平均成一个多位值、速率降 64 倍；FIR 再修平频率响应、滤掉镜频。输出就是普通 PCM，直接进 ALSA / HAL。
SNR

噪声整形

NOISE SHAPING
1-bit 量化本身噪声巨大，但 ΣΔ 环路让噪声低频被压制、高频抬升——恰好音频信号待在低频带。只要抽取滤波器把带外噪声滤干净，带内剩下的就是高信噪比信号。
致命细节：PDM 位流不能当 PCM「按位拼起来」用——跳过抽取滤波器得到的是纯量化噪声（满幅沙沙声）。 主控没有 PDM/DFSDM 外设时，有人用 GPIO+DMA 高频采样再软件抽取：教学可以，产品别这么干（时钟精度与 CPU 都扛不住）。
05

立体声 · 两支麦克风共享一根线

Stereo & Arrays

PDM 的「总线仲裁」朴素到极致：左右各占时钟的一个沿，L/R 引脚一接电源一接地，永不冲突。

架构 A立体声 · 共享 DATA

两支麦克风 L/R 一接地一接电源，分别用下降沿 / 上升沿更新数据；主控在两个沿各采一位。一根 DATA 线，两路音频，互不干扰。

架构 B单声道

只有一支麦克风时，数据只在自己的半相位上翻转；主控仍按 CLK÷64 抽取。想再加一支？直接挂上同一根 DATA、把 L/R 反接即可。

架构 C阵列 · 多路 PDM

回声消除 / 波束成形要 2~8 麦：要么选带多组 PDM 控制器的 SoC（如 RK3308 内置 8 通道 PDM），要么用麦克风阵列前端芯片把多路 PDM 汇成 TDM/I²S 再喂主控。

07

Linux 上的 DMIC · 命令实战

Linux Cheat Sheet

DMIC 在 Linux 里同样归 ALSA / ASoC 管：SoC 的 PDM/DFSDM 控制器负责采码流并硬件抽取，codec 侧用通用的 dmic-codec 绑定。注意：PDM 麦克风没有 I²C 寄存器——增益一律在主控/数字侧调。 点击任意命令行即可复制。

ls — 你的 DMIC 声卡在哪
$ arecord -l # 列出录音设备（找 capture）
card 1: dmic [dmic], device 0
$ cat /proc/asound/cards # 声卡总览
$ dmesg | grep -iE 'pdm|dmic|snd'
asoc-simple-card dmic-sound: dmic ↔ fe410000.pdm mapping ok
rec — 录一段验证
$ arecord -D hw:1,0 -f S16_LE -r 48000 -c 2 /tmp/mic.wav -d 5
# 对着麦克风说话，录 5 秒
$ aplay /tmp/mic.wav # 回放听一听
$ sox /tmp/mic.wav -n spectrogram -o mic.png
# 生成频谱图：看带内是否干净、DC 偏移多大
hw_params — 验证 fs = CLK÷64
# 录音进行中执行（pcm0c = capture）
$ cat /proc/asound/card1/pcm0c/sub0/hw_params
format: S16_LE rate: 48000 (48.000 kHz) channels: 2
→ 反推 CLK = 48000 × 64 = 3.072 MHz，拿示波器对！
amixer — 增益在主控侧调
# PDM 麦克风本体无寄存器，增益 = 主控数字增益
$ amixer -c 1 scontrols
Simple mixer control:'Mic Capture Volume',0
$ amixer -c 1 cset name='Mic Capture Volume' 80%
# 部分平台还提供 DMIC 高通滤波控件（去 DC）
Android — tinyalsa 抓 DMIC
$ adb shell tinycap /sdcard/m.wav -D 0 -d 0 -c 2 -r 48000 -b 16
# 录几秒：Ctrl-C 停止后 adb pull /sdcard/m.wav
$ adb shell grep -i dmic /vendor/etc/audio_policy_configuration.xml
<profile ... samplingRates="48000" format="AUDIO_FORMAT_PCM_16_BIT"/>
# input profile 没声明 dmic → tinycap 打不开设备
dmesg — 出问题先看内核日志
$ dmesg | grep -iE 'pdm|dmic|asoc'
rockchip-pdm fe410000.pdm: ...
→ PDM 控制器 probe 失败 = 时钟/引脚没配好，后面全白搭
$ cat /proc/asound/card1/pcm0c/sub0/status
state: RUNNING xrun: 0 # 欠载计数，断流时增长
DTS — 声卡绑定：dmic-codec + PDM 控制器（以 RK 平台为例）
/* 通用 dmic-codec 绑定：两支 PDM 麦克风共享一根 DATA */
dmic_codec: dmic-codec
{
status = "okay";
compatible = "dmic-codec";
num-channels = <2>; /* ←→ 05 节：两支麦克风 = 两声道 */
ports { dmic_port: port { dmic_ep: endpoint { remote-endpoint = <&pdm_ep>; }; }; };
};
/* SoC 侧 PDM 控制器（各平台节点名不同：RK = pdm · STM32 = dfsdm · ESP32 无 DTS）*/
&pdm
{
status = "okay";
pinctrl-names = "default";
pinctrl-0 = <&pdm_m0_clk &pdm_m0_sdi0>; /* CLK + DATA 引脚复用 */
pdm_port: port { pdm_ep: endpoint { remote-endpoint = <&dmic_ep>; }; };
};
两个高频坑：① 静音时录出来应是「中位」码型（波形贴着零点小幅抖动），若恒 0 / 恒 1 → 上拉或时钟问题（08 节第 2 步）； ② 采样率对不上 → 时钟树配错，回 06 节用 fs = CLK÷64 核对。 另注：树莓派没有 PDM 输入外设，玩 DMIC 请选带 DFSDM / SAI-PDM / PDM 控制器的平台（STM32、ESP32、nRF52/91、RK、MTK…）。

踩坑指南 · 症状 → 病因

Troubleshooting

调 DMIC 的时间几乎都花在下面这些地方。按症状对号入座。

完全
无声
没有时钟 / PDM 外设未使能

PDM 麦克风无时钟即无输出。先用示波器量麦克风 CLK 脚有没有波形，再查设备树 pdm 节点 status 与 pinctrl。时钟停了 DATA 还会进高阻——别被「数据线死掉」迷惑。

恒0
恒1
缺上拉 / 采样沿选错

DATA 恒定一个电平：多半是上拉缺失导致高阻被固定读值，或主控只开了右声道滤波而麦克风接成了左。静音时的正确形态是 0101 中位码型（02 节右下图）。

半周期
打架
两支麦克风驱动了同一个沿

立体声下 L/R 引脚接成一样（都接地或都接电源），两支麦在同一边沿一起驱动 DATA——波形在半周期边界毛刺跳变。一支接地、一支接电源即可。

左右
互换
L/R 引脚电平反了

声像左右颠倒，直接交换两支麦克风的 L/R 接线，或在主控侧交换声道映射。个别厂商 L/R 定义相反，换料时务必重查手册。

变调
加速
CLK 与抽取比不匹配

播放「快进小嗓门」= 实际 fs 与预期不一致。用 06 节公式核对 fs = CLK ÷ 64：时钟树分频错一格，音调就差一截。

直流
偏移
没做高通滤波

PDM 解码天生带直流失调，波形整体浮在零线上方。抽取链路里加 20~50 Hz 高通（很多主控/HAL 有现成控件），别让 DC 吃掉动态范围。

底噪
大
时钟质量 / 走线 / 供电

CLK 抖动直接换算成码流噪声；DATA 线浮空段还可能捡干扰。CLK 与 DATA 短而等长、远离开关电源与射频天线；麦克风 VDD 用独立 LDO + 就近去耦。
