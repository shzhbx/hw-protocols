UNIVERSAL SERIAL BUS · 图解硬件协议

USB2.0+ 通 用 串 行 总 线 · 即 插 即 用 的 帝 国

1996 年，一群工程师想终结机箱背后的「串口并口 PS/2 线缆地狱」，于是发明了 USB：四根线、带供电、插上就能用。 三十年后，从 5 块钱的鼠标到 100 W 的显示器都挂在它上面。往下滚动：看主机如何用两根差分线， 把一个字节经过 NRZI + 位填充送到 127 个设备中的任意一个。

01

它是什么，为什么它赢了

What & Why

一句话：USB 是一根「带供电的、主机说了算的、即插即用的」分层星型总线——统一连接器 + 统一软件栈，让外设彻底免驱动安装、免重启、免供电线。

USB（Universal Serial Bus）1996 年由 Intel / Compaq / Microsoft / DEC 等 seven 家公司联合推出， 1998 年的 USB 1.1 搭上 iMac 与 Windows 98 才真正普及。它一次性解决了三件事： 统一连接器（终结串口/并口/PS2/游戏口各自为政）、内置供电（5 V VBUS，小设备连电源线都省了）、 即插即用（插入 → 枚举 → 驱动自动加载，全程无需重启）。

它的拓扑与 I²C / SPI 那种「对等共享总线」有本质区别： USB 是分层星型（Tiered Star）——主机（含根集线器）在树根，集线器向外分叉，设备是叶子。 每一段线缆都是点对点；树上的任何通信都必须由主机发起（主机轮询模型），设备永远不能主动「插话」， 只能在被轮询到时回答。这与 CAN 的多主仲裁、I²C 的从机应答是两种世界观。

设备用 7-bit 地址区分（地址 0 保留给「刚复位还没分配地址」的设备），所以一条总线上最多 127 个设备；级联最多 5 级集线器（含根集线器共 7 层），每段线缆全速/高速 ≤5 m。 主机每 1 ms（全速）或 125 µs（高速微帧）发一帧， 帧头是广播的 SOF 令牌——所有传输都排布在帧内调度。

FACT / A

四根线的极简主义 VBUS D+ D− GND

屏蔽双绞的差分对 D+/D− 扛全部数据，VBUS 供电。连接器永远「A 口朝主机、B 口朝设备」，插反了物理上就插不进去——这是刻意设计。

FACT / B

主机是唯一的「大脑」HOST-CENTRIC

没有仲裁、没有冲突检测：主机控制器轮询调度一切。想理解 USB 的任何行为，先问一句「主机现在在轮询谁」。

FACT / C

上电即自我介绍 ENUMERATION

插入瞬间，设备用一只上拉电阻报身份、用描述符自述「我是谁、我要多少电流、我有哪些端点」——这就是 06 节的枚举流程。

FACT / D

供电也是协议的一部分 VBUS

未配置设备只许取 100 mA（一个单位负载），配置后按描述符申报的 bMaxPower 供给，最高 500 mA；集线器还要再做一次电流分配。

02

物理层 · 两根线，四种线态

Physical Layer

D+/D− 是一对90 Ω 差分阻抗的双绞线（和 CAN、RS-485 一样吃差分信号的抗干扰红利）。 但 USB 的精妙在于：靠两根线上的电平组合，不用额外引脚就表达出 J / K / SE0 / SE1 四种线态——数据、复位、包结束、速度识别全在这一对线上。

D+ / D−差分数据对 · 半双工90Ω TWISTED

数据在两根线上差分传输：D+ 为高、D− 为低是一个线态，反过来是另一个。发送方交替驱动（推挽），总线上同一时刻只有一方在说话——半双工。上面每格背景色就是当前线态。

V(D+) − V(D−) > +200 mV 或 < −200 mV 才算有效差分
上拉电阻速度识别 · 唯一的「自我介绍」1.5 kΩ

主机在 D+/D− 上各挂 15 kΩ 下拉，空闲时双双为低（SE0）。设备插入后经 1.5 kΩ 上拉到 3.3 V：拉 D+ = Full-Speed，拉 D− = Low-Speed——分压后约 3.0 V，主机一眼识别。高速设备随后再握手升级。

编码实验室 · NRZI + 位填充

Interactive · Bit Stuffing

USB 2.0 的灵魂在这里：数据没有时钟线（这一点和 UART 一样），但接收端要用数据本身的电平翻转来恢复时钟。 于是两级流水线：① 位填充——连着 6 个 1 之后强制插一个 0；② NRZI 编码——0 让电平翻转、1 让电平保持。 净效果：电平永远不会连续 7 个位时间不动，时钟永远追得上。换字节、单步、点任意一列试试。

0 翻 1 保 · 六一塞零NMZI + BIT STUFFING

反过来想：全 1 的数据（0xFF）如果直接 NRZI，电平会一直不动，接收端的时钟立刻失锁。 塞进一个 0，就制造了一次翻转。这就是为什么 USB 线上传 0x00 比传 0xFF 更「累」（0=每拍都翻转）， 以及为什么最坏情况下有效带宽要打约 1/7 的折扣——协议把这一切都提前算好了。

踩坑指南 · 症状 → 病因

Troubleshooting

USB 的问题八成不在协议，而在线缆和电。按症状对号入座。

插上
没反应
完全枚举不到 · VBUS / 上拉 / 线序

查三处：VBUS 有没有 5 V（劣质延长线只通 D+/D− 也有）、设备 1.5 kΩ 上拉是否在 D+（FS）/D−（LS）、D+/D− 是否接反。dmesg 一行不吐 = 主机根本没看到上拉。

枚举
一半失败
device descriptor read/64, error -71 / -110

-71（EPROTO）= 有响应但数据坏：线缆过长/劣质、EMI、SMA 走线；-110（超时）= 设备没理主机：上电时序没完成、复位太短。先换一根短的原装线再谈别的。

硬盘
咔哒掉线
供电不足 · 压降与电流配额

2.5″ 硬盘起步 500 mA、寻道瞬间更高：总线供电 hub 每口只给 100 mA，长细线再压掉零点几伏（08 节计算器算过）。症状：认盘 → 掉盘循环。解法：自供电 hub / 双头取电线 / 短粗线。

hub 口
全失效
over-current condition 触发保护

某口设备短路或虚标电流，hub 整体断电自保，dmesg 刷屏 over-current。拔掉肇事设备即可恢复；若反复出现，查外设的 VBUS 对地短路。

高速
变全速
Hi-Speed 握手失败降级

高速 chirp 协商（复位期间的 K/J 序列）对线缆质量敏感：握手失败就静默退回 480M→12M。lsusb -t 看到 12M 而设备标称 480M，先换线；dmesg 会有 not running at top speed 提示。

WiFi
跟着变卡
USB 3.0 射频泄漏干扰 2.4 GHz

SS 高速信号的谐波正好落在 2.4 G 频段：USB3 硬盘挨着 WiFi 天线/接收器，吞吐腰斩。经典解法：换屏蔽良好的线缆、把设备挪远 20 cm、WiFi 改 5 GHz。

睡醒
失联
autosuspend 把设备挂起了

内核默认对部分设备开自动挂起（线态维持 J 超过 3 ms 即 Suspend），唤醒失败的设备就失联：echo -1 > …/power/autosuspend 或内核参数 usbcore.autosuspend=-1 排除。

六条铁律
  • 1主机是唯一发起者——没有令牌，设备一个字也不能说
  • 2插入三件事：上拉报速度 → 复位 → 地址 0 上读摸底 8 字节
  • 30 翻 1 保、六一塞零——NRZI + 位填充是时钟恢复的命根
  • 4四种传输各司其职：控制必选，批量吃余量，中断保延迟，同步保带宽不重试
  • 5描述符即真相——lsusb -v 看到什么，主机就相信什么
  • 6先算电再谈速——压降超 0.25 V，再快的协议也白搭
