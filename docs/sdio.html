SDIO 无 线 模 块 的 高 速 通 道 · SDIO 协 议 详 解

把 SD 存储卡的物理层借来接外设，就是 SDIO。手机和智能音箱里的 WiFi/蓝牙 combo 模块， 八成就挂在这 6 根线上：CMD 线一问一答 48-bit 命令帧，DAT0-3 四位并行搬数据。 往下滚动，看一次完整的 CMD53 块读事务逐位展开。

01

它是什么，为什么需要它

What & Why

一句话：SDIO 是 SD 协会在 SD 卡物理层之上定义的外设接口——命令格式、CRC、上电时序与 SD 卡同源，只是把「存数据」换成了「接外设」。

SDIO（Secure Digital Input/Output）2001 年由 SD 协会发布，复用 SD 卡的 CLK/CMD/DAT 引脚与命令体系。 最成功的应用就是无线连接：手机、平板、智能音箱里的 WiFi/BT/FM combo 模块—— CYW43438 / RTL8189 / AP6212 / ESP8089——几乎清一色 SDIO； 早年还有 GPS、CMMB 移动电视、指纹模块，树莓派 3/4/5 的板载 WiFi 同样是 SDIO。

为什么不用 SPI 或 UART？WiFi 吞吐动辄几十 Mbps：UART 跑不动，SPI 也是串行； SDIO 用 6 根线做到 4-bit 并行 + 50 MHz，还有 DMA 友好的块传输与现成的 Linux mmc 子系统。 代价是复杂度：枚举是一套完整状态机（CMD5 → CMD3 → CMD7），寄存器要通过配置区 CCCR 间接访问，调试链路比 SPI 长得多。

与 SD 卡的关键区别：SD 卡用 ACMD41 协商电压并枚举存储面；SDIO 卡用 CMD5。 SDIO 卡内部最多 7 个 function（FN1-7），FN0 是固定的配置区（CCCR/CIA）—— 驱动先在 FN0 里开关功能、配位宽与速度，再去 FN1（通常是 WiFi 数据面）收发。

FACT / A

生于 SD 卡协议 CMD5

命令、CRC、上电时序全部继承自 SD 存储卡；但枚举入口是 CMD5（IO_SEND_OP_COND）而非 ACMD41——这是驱动层的第一个分叉。

FACT / B

一根半双工命令线 CMD

主机的命令与卡的响应共用 CMD：永远是 48-bit 定长帧（R2 长响应除外），起始位 0、停止位 1，帧尾带 7-bit CRC7。

FACT / C

四位并行 + 块校验 DAT0-3

数据只在 CMD52/CMD53 放行后才走 DAT 线；每个数据块尾随 16-bit CRC16。1-bit 模式只用 DAT0——模块降级运行时就是这样。

FACT / D

七个功能槽 FN0-7

FN0 = CCCR/CIA 配置区（位宽、高速、中断、功能开关）；FN1-7 挂具体外设。WiFi 模块几乎都是 FN1 = 802.11 数据面。

02

六根信号线（+供电与上拉）

Signals

SDIO 的信号世界：一根时钟、一根命令、四根数据，仅此而已。每张卡片里都是正在运行的实时波形。

CLKSD CLK / 时钟CLOCK

主控单向驱动的时钟，所有 CMD/DAT 位都与它对齐，接收端在上升沿采样。初始化阶段必须 ≤ 400 kHz，枚举完成后才提速——直接上高速，卡根本来不及回应：

400 kHz（枚举）→ 25 MHz（DS）/ 50 MHz（HS）
CMD命令与响应 · 半双工COMMAND

主机的 48-bit 命令与卡的响应共用同一根线：起始位 0、停止位 1 划出帧界，方向位区分谁在说话（上图绿色=主机、琥珀色=卡）。推挽驱动 + 上拉：

帧 = 01 + 命令号×6 + 参数×32 + CRC7 + 1 = 48 bit
DAT0-34-bit 数据 / DAT1 兼中断DATA

数据线：1-bit 模式只用 DAT0，4-bit 时四根线并行搬 nibble。DAT1 空闲时兼职 SDIO 中断（拉低=卡有事要说）；DAT3 在 SPI 兼容模式兼作片选：

4-bit × 50 MHz ⇒ 200 Mbps ≈ 25 MB/s
VDD供电 · 上拉 · 去耦AUX

供电 2.7–3.6 V 就近放 100 nF 去耦。每根 CMD/DAT 线都要 10–50 kΩ 上拉：总线空闲时的高电平全靠它维持——没上拉，空闲电平漂移，枚举直接超时：

R_PULL = 10–50 kΩ（CMD、DAT0-3 每根都要）

04

命令与响应 · 四个数字背下来

Commands & Responses

SDIO 的协议层由四个数字撑起：48（帧长）· 32（参数位）· 7（命令校验）· 16（数据块校验）。

CMD

48-bit 命令帧解剖

COMMAND FORMAT
起始位 0 与发送方位（主机=1，卡=0）打头，6-bit 命令号 + 32-bit 参数占中间，CRC7 收尾、停止位 1 封口。所有位 MSB 先发，与 CLK 上升沿对齐。上图示例正是 03 节动画里的 CMD53。
RSP

响应类型一览

RESPONSES
R1 最常见（32-bit 卡状态字）；SDIO 特有 R4（CMD5 回 OCR）与 R5（中断式读写）；R2 是 136-bit 长响应，仅 SD 存储卡用来回 CID/CSD，SDIO 用不到。
CRC

双校验体系

CRC7 + CRC16
CMD 线每帧 7-bit CRC7（多项式 x⁷+x³+1，覆盖前 40 bit）；DAT 线每块 16-bit CRC16（0x1021）。校验失败协议层不重发——控制器报错，由 WiFi 驱动 / TCP 上层重传。
CMD52/53

SDIO 的精髓：点访问 vs 块访问

POINT vs BLOCK
CMD52 点访问：一次一个寄存器字节，数据藏在参数里往返，不占 DAT 线——读写 CCCR、开关功能全靠它；CMD53 块访问：FIFO 式成块搬运、支持多块与 DMA——固件下载、网络收发全靠它。两者相差约 50 倍吞吐。
致命细节：SDIO 卡 ≠ SD 卡。枚举用 CMD5 而非 ACMD41；combo 卡（SD 存储 + SDIO 无线）两条枚举流程都要走完。 拿 SD 卡代码直接枚举 WiFi 模块，CMD5 会永远无响应——表现为内核日志里的超时 error -110。
05

初始化 · 从上电到第一个数据块

Enumeration Flow

上电到能收发，中间是一套严格的状态机：CMD5 查协商 → CMD3 拿地址 → CMD7 选中 → CCCR 配置 → 使能功能，一步都不能跳。

形态 A纯 SDIO 模块

只有 IO 面：ESP8089、CYW43362/43438、RTL8189。CMD5 枚举完成后，FN0 的 CCCR 配位宽与高速，FN1 就是 WiFi 数据面。手机与音箱里的主力形态。

形态 BCombo 卡 · 双面枚举

SD 存储 + SDIO 无线双功能：AP6181 / AP6212 等 AMPAK 模块。ACMD41 与 CMD5 两条枚举都要走；Linux 会同时出现 mmcblk 块设备与 sdio 功能设备。

形态 CSoC 侧 · mmc 控制器

RK / Allwinner / STM32 的 SDMMC·SDHCI 控制器。设备树三件套：non-removable（焊死模块）+ bus-width=<4> + cap-sdio-irq（DAT1 硬件中断），WiFi 场景还要 keep-power-in-suspend。

Linux 上的 SDIO · 命令实战

Linux Cheat Sheet

SDIO 设备在 Linux 里挂 mmc 总线：控制器 → sdio bus → function driver。WiFi 模块的「网卡」，就是 SDIO 功能设备 FN1 被 brcmfmac / rtl8xxxu 等驱动接管后的样子。点击任意命令行即可复制。

ls — 你的模块在哪
$ ls /sys/bus/sdio/devices # FN 级功能设备
mmc1:0001:1 # 总线1 · 地址0001 · 功能1
$ cat .../mmc1:0001:1/{vendor,device,class}
0x02d0 0xa9a6 0x02 # 博通 43438 · WLAN 类
dmesg — 枚举是否成功
$ dmesg | grep -iE 'mmc|sdio'
mmc1: new high speed SDIO card at address 0001
brcmfmac: F1 signature OK, firmwares loaded
error -110 whilst initialising SDIO card ← 超时：卡没响应 CMD5
ios — 当前总线参数
# 需要 root（debugfs）
$ cat /sys/kernel/debug/mmc/ios
clock: 50000000 Hz bus width: 4 bit
timing: SD HS signal voltage: 3300
# 若 25 MHz / 1 bit → 高速或位宽没打开（08 节第 4 步）
iw — WiFi 数据面验证
$ ip link set wlan0 up && iw dev wlan0 link
Connected to aa:bb:cc:dd:ee:ff (on wlan0)
freq: 2437 signal: -46 dBm tx bitrate: 72.2 MBit/s
$ iperf3 -c 192.168.1.10 -t 10 # 对 06 节理论值
fw — 固件加载
$ dmesg | grep -iE 'firmware|brcmfmac|rtl8xxxu'
brcmfmac: firmware: brcm/brcmfmac43430-sdio.bin
$ ls /lib/firmware/brcm/
Direct firmware load failed → 缺文件或 modalias 不匹配
Android — adb 视角
$ adb shell ls /sys/bus/sdio/devices
$ adb shell dmesg | grep -iE 'mmc1|sdio|brcm'
# 固件在 /vendor/firmware（已链接到 /lib/firmware）
$ adb shell cmd wifi status # WiFi 状态
DTS — WiFi 模块三件套 + 驱动绑定（通用示例）
/* SoC 的 mmc 控制器：焊死的 SDIO WiFi 模块 */
&mmc1
{
status = "okay";
bus-width = <4>; /* ←→ 06 节：4-bit = DAT0-3 */
cap-sdio-irq; /* DAT1 兼职硬件中断 */
non-removable; /* 焊死模块：跳过拔卡检测 */
keep-power-in-suspend; /* 睡眠不断电 → 支持唤醒 */
pinctrl-0 = <&mmc1_clk &mmc1_cmd &mmc1_d0 &mmc1_d1 &mmc1_d2 &mmc1_d3>;
};
/* 部分平台还需在控制器节点下声明 wifi 子节点（compatible 指向具体驱动）*/
两个高频坑：① error -110 超时 = 卡对 CMD5 无响应，先查上电/上拉（08 节第 2 步）； ② 吞吐只有几 MB/s → ios 里多半是 1-bit 或 25 MHz（08 节第 4 步）。 另注：树莓派 3/4/5 的板载 WiFi 正是 SDIO，它是最好的实验台。

09

踩坑指南 · 症状 → 病因

Troubleshooting

调 SDIO 的时间几乎都花在下面这些地方。按症状对号入座。

完全
枚举不到
error -110 超时 · 没上电 / 没复位 / 没上拉

SDIO 模块对上电时序比 SD 卡挑剔得多：查 REG_ON 使能脚的拉高时序、每根 CMD/DAT 的 10–50 kΩ 上拉、CLK 枚举阶段是否 ≤ 400 kHz。-110 是「无响应」，先查硬件再查软件。

CRC
刷屏
error -84 · 走线 / 信号完整性

先把 ios 降到 25 MHz 或切 1-bit 复测：错误消失 → 走线太长 / 不等长 / 上拉阻值不当；依旧出错 → 查焊接与电源纹波。50 MHz 下等长没做好是重灾区。

只能
1-bit
4-bit 起不来 · DAT1-3 没配好

三处排查：pinctrl 是否把 DAT1-3 复用到位、设备树 bus-width=<4> 是否写了、模块 CCCR 是否支持 4-bit（罕见不支持）。ios 的 bus width 一看便知。

速度
卡 25M
High Speed 没使能

枚举成功但 ios 里 clock=25000000：驱动没置 CCCR 的高速位，或设备树没开 cap-sd-highspeed。25 MHz 的 4-bit 只有 12.5 MB/s，WiFi 明显跑不满。

睡醒
失联
suspend 断电 · 唤醒后不重枚举

没开 keep-power-in-suspend，睡眠时模块掉电；或 cd-gpios 误报「拔卡」——焊死的模块必须 non-removable。症状：唤醒后 wlan0 消失或永久 -110。

中断
失效
cap-sdio-irq 未开 · 驱动退化轮询

SDIO 的中断靠 DAT1 拉低通知；没开硬件中断，WiFi 驱动只能用 CMD52 轮询——CPU 占用高、延迟抖动大。确认 dts 的 cap-sdio-irq 与 DAT1 引脚未被挪用。

固件
加载失败
Direct firmware load failed

固件文件名与设备树 / 驱动版本不匹配；换内核后 brcmfmac 需要配套 -sdio.bin + NVRAM + clm_blob 三件。dmesg 里看它到底在找哪个文件，缺什么补什么。
