01红外遥控：用光传数据 INFRARED REMOTE CONTROL OVERVIEW

红外（IR）遥控是 单向无线 通信：遥控器上的红外 LED 以 940 nm 左右的近红外光为载体， 按 NEC / RC-5 / SIRC 等协议的时序规则亮灭；设备端的一体化接收头（如 VS1838B）把光信号还原成电平， 交由 MCU 解码。没有时钟线、没有应答、不能穿透墙壁 —— 但足够便宜、功耗极低、闲时零辐射， 四十年来统治着客厅里每一个遥控器。

→单向 Simplex

只能遥控器 → 设备，设备不回话。因此协议全靠发端自律：反码校验、连发多帧、重复码，全是「防丢」手段。

〜载波抗扰

数据被调制到 38 kHz 载波上。接收头内置带通滤波器只认这个频率的「闪烁」，恒定的阳光与灯光被直接滤除。

◱视距传播

光走直线：不能穿墙，斜着对也能反射到（墙面/天花板）。典型距离 5~10 m，视角约 ±45°。

⌂无处不在

电视、空调、机顶盒、风扇、投影仪……绝大多数国产家电用 NEC 或其变体；学会 NEC 就看懂了 90% 的遥控器。

02载波与调制：为什么要「闪烁」？ 38 kHz CARRIER · MODULATE → DEMODULATE

环境里到处是红外光：太阳、白炽灯、人的体温。若直接「亮=1、灭=0」，接收端根本分不清数据与环境光。 红外遥控的办法是：数据不直接点亮 LED，而是先「亮灭闪烁」在 38 kHz 载波上 —— 有载波的时段代表一个脉冲（burst），无载波代表空闲（space），脉冲 + 空闲的宽度组合编码出 0 和 1。 下图三层对照：想发的数据 → 空中实际的调制光 → 接收头输出的解调电平（注意反相且低有效）：

3-LAYER VIEW
载波周期 26.3 µs占空比 1/3560 µs 脉冲 ≈ 21 个载波周期
① 基带：想发送的位流 ② 空中：38 kHz 调制后的红外光 ③ 接收头 OUT：解调 + 反相（有光=低！）

☀抗环境光

接收头内是 38 kHz 带通滤波 + 解调：阳光是直流、灯光闪烁在 100/120 Hz，都落在通带之外 —— 只有「按 38 kHz 闪」的光能通过。这一招就叫调制。

⅓占空比 1/3

载波每个周期只亮 1/3（8.8 µs/26.3 µs）。平均电流不变的前提下峰值电流可以更大 → 发射更远，LED 更省电。36/38/40/56 kHz 是常见载波家族。

▣一体化接收头

VS1838B / TSOP 系列：光电二极管 + 放大 + AGC + 带通滤波 + 解调 + 驱动，全在一颗三脚器件里。VCC / GND / OUT，空闲时 OUT=高，收到载波拉低，MCU 直接读电平。

03NEC 帧解剖：引导码 + 四个字节 NEC FRAME ANATOMY · ADDR=0x00 CMD=0x45

NEC 是最常见的红外协议（38 kHz 载波）。一帧 = 9 ms 引导脉冲 + 4.5 ms 引导空闲，随后 32 个数据位：地址、地址反码、命令、命令反码各 8 位，低位（LSB）先行。 位编码规则极简：载波固定 560 µs，看后面的空闲 —— 空闲 560 µs=“0”， 空闲 1.68 ms=“1”。把鼠标放到波形上（或点击右侧条目）逐段查看：

重复码：按住不放时发什么？

按住按键：完整帧只发一次，之后每 110 ms 发一个「9 ms + 2.25 ms + 560 µs」重复码 —— 空调的连发调温、电视的长按音量都靠它。

06解码实战：从脉冲串到键值 DECODER STATE MACHINE · STEP BY STEP

解码不测载波本身，只测「载波出现/消失的时长」。接收头 OUT 在每个边沿触发中断，用微秒定时器记录每段宽度， 状态机按宽度窗口判决（容差通常 ±20%）。左边是真实的测量日志（mode2 风格）， 点「下一步」看状态机如何一步步把 32 位吃进来（帧内容：地址 0x00 · 命令 0x45）：

#include <IRremote.hpp> // IRremote 4.x void setup(){ Serial.begin(115200); IrReceiver.begin(11, ENABLE_LED_FEEDBACK); // 接收头 OUT → D11 } void loop(){ if(IrReceiver.decode()){ if(!(IrReceiver.decodedIRData.flags & IRDATA_FLAGS_IS_REPEAT)){ Serial.print(IrReceiver.getProtocolString()); // "NEC" Serial.print(" addr=0x"); Serial.print(IrReceiver.decodedIRData.address, HEX); Serial.print(" cmd=0x"); Serial.println(IrReceiver.decodedIRData.command, HEX); } IrReceiver.resume(); // 准备接收下一帧 } }

裸机解码要点（无库）

  • 1双边沿外部中断 + 微秒计时器：上升/下降沿各记录一次时长，得到 pulse/space 序列
  • 2按窗口判决：9ms±20% 判引导、空闲 [0.34,1.12)ms→“0”、[1.12,2.2]ms→“1”
  • 3先收满 32 位再校验：addr^invAddr==0xFF 且 cmd^invCmd==0xFF，否则整帧丢弃
  • 4区分重复码：引导后空闲 2.25 ms → 不进数据态，直接置「重复」标志

软件层的常见约定

「按一下」通常在收到首帧时执行动作；「长按连发」由重复码驱动（如音量持续增）。 为防误触发，很多解码器要求 同一键值连续 2 帧一致才生效 —— NEC 单帧即带反码校验， 但干扰强的地方（日光灯镇流器）仍然建议加这个软件滤波。

!忘了输出反相

接收头有载波 = 低电平。把逻辑分析仪波形和协议文档的发射图直接对比，会觉得「完全反了」—— 其实没错，先反相再分析。用库时它已替你处理。

≠载波不匹配

36 / 38 / 40 kHz 接收头带通不同：拿 40 kHz 遥控器对 38 kHz 接收头，距离骤降、丢帧严重。换设备先查载波频率 —— ir-ctl -r -m 都收不到脉冲时首先怀疑它。

☀环境光干扰

阳光直射会让接收头前级饱和；老式节能灯/日光灯的 100 Hz 闪烁与开关电源噪声会制造假脉冲。遮光筒、缩短距离、换个角度，立竿见影。

◔首帧被 AGC 吃掉

接收头自动增益需要引导码「热身」：安静很久后的第一帧可能解不出。所以 NEC 才设计成按住连发 —— 发送端重要指令至少连发 2~3 帧。

⚡电池老化

遥控器「时好时坏、离近了才行」≈ 电池电压不足 → LED 峰值电流下降 → 距离骤减。先换电池再查电路，能省一下午。

⏚接线与去耦

接收头 VCC 就近加 100 nF 去耦（串 100 Ω + 大电容更佳），否则电源纹波直接耦合进 OUT；MCU 侧务必用双边沿中断而不是轮询，微秒级时宽轮询必丢。

GOLDEN RULES

六条铁律

  • 1数据骑在 38 kHz 载波上 —— 不是简单的亮/灭
  • 2接收头输出低有效：有载波 = OUT 拉低
  • 3NEC 位序 LSB 先行 —— 抓包按低位先读（最易忘！）
  • 4反码校验：addr^inv==0xFF、cmd^inv==0xFF 才收
  • 5按住 = 110 ms 重复码，完整帧只发第一遍
  • 6视距通信：不穿墙，载波频率要对上
GLOSSARY
Carrier · 载波
承载信息的固定频率振荡（红外遥控为 36/38/40 kHz 光脉冲），用于与环境光区分
Modulation / Demodulation
把数据「骑」到载波上 / 从载波上取下来；一体化接收头自动完成解调与反相
Burst / Space · 脉冲/空闲
载波亮起的时段 / 熄灭的时段；红外协议用两者的宽度组合编码信息
Leader · 引导码
帧开头的固定图形（NEC: 9ms+4.5ms），宣告「我要发了」并给 AGC 热身时间
AGC · 自动增益控制
接收头根据信号强度自适应放大倍数；需要引导码做调整基准
Repeat Code · 重复码
按住按键时周期性发送的短码（NEC: 9+2.25+0.56ms），表示「还按着」
Inverse Check · 反码校验
每字节附上按位取反的备份字节，收端异或校验 —— 无重传协议下的廉价检错
Manchester · 曼彻斯特编码
位中点跳变方向表示 0/1 的编码（RC-5/RC-6），数据自带时钟信息
Scancode · 扫描码
协议无关的键值抽象；Linux 内核中 NEC 记为 16 位 地址<<8|命令
