I2C 协议详解

两根线、一主多从、每个字节都有回执。I²C（Inter-Integrated Circuit）是芯片之间最常用的对话方式—— 从 EEPROM、传感器到 OLED 屏幕都在用它。本页用可交互的动画波形， 把 I²C 的每一个时钟周期拆开给你看。

SDA — SERIAL DATA · SCL — SERIAL CLOCK · OPEN-DRAIN + PULL-UP

01

一图看懂 I²C

Overview

I²C 是一种同步、半双工、多从机寻址的两线制串行总线：主机（通常是 MCU）产生时钟 SCL， 数据在 SDA 上双向流动。所有器件并联在这两根线上，靠地址区分彼此。

LINE ×2

只要两根线

SDA 数据线 + SCL 时钟线，再加共地即可。同步通信不需要约定位速率，时钟随数据一起发送。

ADDR 7-BIT

地址寻址

每帧以 7 位从机地址开头（另有 10 位扩展），总线上理论可挂 112 个可用地址（128 − 16 个保留）。

ACK / NACK

自带回执

每传完 8 位，第 9 个时钟是应答位：接收方拉低 SDA 表示“收到”。链路断了、地址错了，主机立刻知道。

WIRED-AND

开漏 + 线与

所有输出都是开漏（open-drain）：只准拉低、不准驱高，高电平交给上拉电阻。天然避免多器件驱动冲突。

MULTI-MASTER

支持多主机

两个主机同时开口？仲裁机制逐位裁决，输家自动闭嘴转听众，数据一位都不丢。

CLOCK

主机给时钟

全部时钟由主机产生——唯一的例外是时钟拉伸：从机可以拉住 SCL 说“等等我”。

02

物理层：开漏、上拉与线与

Physical Layer

I²C 的所有魔法都来自一个电路结构：开漏输出 + 上拉电阻。任何器件都只能把线拉低到地， 没人能“强行”输出高电平——高电平是总线空闲时由上拉电阻“吊”上去的。于是两根线实现了线与（wired-AND）： 只要有一个器件拉低，总线就是低。

总线拓扑 · 1 主 2 从

挂载方式：所有器件的 SDA 并联、SCL 并联。主机发起读写，从机被动应答； 绿点/黄点是总线上奔跑的信号。悬停芯片可看它扮演的角色。

线与实验台 · 点击器件切换「拉低 ⇄ 释放」
SDA = 1 · 1 = 1（线与） 全部释放 → 上拉电阻拉高

结论：谁都可以拉低、没人能驱高 → 多器件同挂一线也不会电源对撞。 START/STOP、ACK、仲裁、时钟拉伸……全都靠这个「线与」。

上拉电阻怎么选
  • 100 kHz：常用 4.7 kΩ
  • 400 kHz：常用 2.2 kΩ
  • 最小值由灌电流能力决定（约 3 mA）
  • 最大值由上升时间 tr 与总线电容 Cb 决定
总线电容上限

标准/快速模式规定总电容 Cb ≤ 400 pF。 走线越长、器件越多，RC 上升沿越缓——波形变成“圆弧”时就是上拉太弱或线太长的信号。

最常见的新手错误

忘记上拉电阻 → 总线永远读低、通信完全失败。 其次是两个电平域直连（3.3V ↔ 5V），需要 MOSFET 电平移位电路。

03

起始与停止条件

Start / Stop

I²C 有一条铁律：SDA 只能在 SCL 为低电平时变化。全世界只有两个例外—— 起始和停止条件，它们恰好用「SCL 高电平时 SDA 的跳变」来当帧边界标记：

起始条件 S · SDA 下降沿

START：SCL 保持高，SDA 从高 → 低。宣告「一次传输开始，下面是地址」。

停止条件 P · SDA 上升沿

STOP：SCL 保持高，SDA 从低 → 高。传输结束，主机释放总线。

重复起始 Sr · 换方向但不松手

读传感器的典型流程：先写寄存器地址、再读数据。如果中间发 STOP，其他主机就可能插进来抢总线。 解决办法是重复起始（Repeated START, Sr）——不发 STOP，直接再来一次 START，波形与 S 完全相同， 但语义是「方向翻转、总线我继续占着」。实验室的「读取」示例里有它的完整动画。

04

数据帧：位序、有效性与应答

Data Framing

每个字节 8 位、高位（MSB）在前，随后跟一个应答位——所以 I²C 世界里一切传输都是 9 的倍数个时钟。看动画里两条竖带：绿色区间允许 SDA 变化，红色区间 SDA 必须纹丝不动。

数据有效性 · 循环演示

规则：SCL 低 → 发送方可搬动 SDA；SCL 高 → 接收方采样，SDA 必须稳定。 违反它（SCL 高时 SDA 跳变）不是被读错数据，就是被解析成 START/STOP。

一帧的解剖
S

起始条件后，主机先发 7 位从机地址 + 1 位方向（R/W）。

9th

第 9 个时钟 = 应答位。发送方释放 SDA，接收方拉低 = ACK「收到」；保持高 = NACK「不在/不要了」。

MSB

字节内高位在前。0x50（101 0000）发出去的顺序是 1,0,1,0,0,0,0。

!

地址没人应答（NACK）：多半是地址错、器件没焊好、或忘了上拉。主机应发 STOP 释放总线后重试。

保留地址（7 位寻址中的 16 个特殊码）
地址用途
0000 000广播地址 General Call——对所有器件说话（如软件复位），多数器件默认忽略
0000 001START 字节——给没有 I²C 硬件、靠轮询的慢速 CPU 一个廉价唤醒方式
0000 01XCBUS 兼容（历史保留）
0000 1XX高速模式主机码——进入 Hs 模式的暗号
1111 0XX10 位寻址前缀（11110 + A9 A8，第二个字节再发低 8 位）
1111 1XXDevice ID——读器件身份证（厂商/型号/版本）

06

时钟拉伸

Clock Stretching

主机虽然掌控时钟，但从机有一个合法的「暂停键」：在 ACK 之后继续把 SCL 按在地上。 主机发现 SCL 不肯升高，就只能等——这叫时钟拉伸。EEPROM 内部写周期、传感器模数转换，都靠它拖时间。 这是 I²C 中唯一允许从机驱动 SCL 的场景。

从机拉住 SCL · 循环演示

看 SCL 中间那段被拉长的低电平：第 9 个时钟（ACK）之后，从机一直按住 SCL 不放； 主机早已释放自己的 SCL 驱动（想给时钟了），但线与让总线保持低。直到从机准备好，才松手让传输继续。 实战提示：不少 USB 转 I²C 适配器不支持拉伸，读某些传感器会莫名超时——原因就在这。

07

多主仲裁

Multi-Master Arbitration

两个主机同时开口会怎样？I²C 的答案优雅到极致：边发边听，逐位对表。 每个主机发出 1 之后都检查总线——如果自己发的是 1、读回来的却是 0，说明有人在拉低， 你输了：立即停止驱动 SDA，转成从机听众。因为判决发生在发送过程中，数据一个位都不浪费。

两个主机抢总线 · 循环演示
总线 SDA（线与结果） M1 输出 M2 输出 SCL（两主机时钟自动同步）

本例：M1 想寻址 0x51、M2 想寻址 0x50。 地址前 6 位相同（101 000…），到最低位 A0：M1 发 1、M2 发 0，线与后总线是 0—— M1「说 1 听 0」，当场认输退出（进入高阻），M2 浑然不觉地继续它的传输。 地址若完全相同，就继续在数据位里比出胜负。

08

五种速度模式

Speed Modes

I²C 向下兼容：快速模式器件在 100 kHz 总线上照常工作。速率越高，对上拉电阻和总线电容越苛刻。

模式速率上拉/驱动要点
标准 Standard100 kbit/s开漏 + 上拉（典型 4.7 kΩ）1982 年初版，兼容性最好；总线电容 ≤ 400 pF
快速 Fast400 kbit/s开漏 + 上拉（典型 2.2 kΩ）1992 年加入；支持从机在 ACK 后时钟拉伸
快速+ Fast-plus1 Mbit/s开漏 + 更强上拉对驱动电流和走线要求更高
高速 High-speed3.4 Mbit/s主机码后切换电流源上拉主机先发主机码 0000 1xxx 进入；从端仍是开漏
超快 Ultra-fast5 Mbit/s推挽输出USD 模式：单向广播、无 ACK、无开漏——严格说是 I²C 的“单行道版”

怎么选：传感器/OLED 用 400 kHz 足够；同一批器件速率不同就就低不就高；长线/面包板场景降到 100 kHz 更稳。

09

实战与调试

Field Notes

理论到此为止——下面是示波器前真正会遇到的问题。

总线「卡死」在低电平

某从机在字节中间复位，SDA 被永久按低。经典恢复术：主机手动补 9 个 SCL 让从机移完剩余位，再发一个 STOP。许多 MCU 的 I²C 外设内置此恢复序列。

上拉电阻的边界

下限由灌电流（约 3 mA）决定：3.3 V 时约 1.1 kΩ；上限由上升时间决定：tr ≈ 0.85·Rp·Cb，标准模式要求 ≤ 1000 ns。上升沿变圆 → 减小 Rp 或减短走线。

地址冲突

两个器件都固定在 0x50？用它们的 A0/A1/A2 地址引脚错开；实在不行换型号或加 I²C 多路复用器（TCA9548A）。先跑一遍 i2cdetect 扫描 列出在线地址。

仪器是标配

逻辑分析仪（采样率 ≥ 10× SCL）开 I²C 解码，地址、ACK、字节一目了然；示波器则用来看模拟质量：上升沿陡不陡、低电平是否真低（<0.4 V）。

跨电平域

3.3 V MCU 接 5 V 器件：两颗 BSS138 MOSFET + 各自上拉即可双向移位，成品模块几毛钱。切勿靠两个上拉“凑合”出中间电平。

信号完整性

走线尽量短（<30 cm 级别）、SDA/SCL 并肩走且下方完整地回流；振铃可串 22–33 Ω 抑制；不稳就降速——I²C 的可靠优先于速度。

Linux 实战：i2c-tools

Linux Command Line

Linux 把每条 I²C 控制器映射成字符设备 /dev/i2c-N，用户态的标配工具包是 i2c-tools（Debian/Ubuntu：apt install i2c-tools）。 下面是一台可交互的虚拟终端：虚拟板卡的总线 i2c-1 上挂着 EEPROM 0x50、 RTC 0x51 和 MPU6050 0x68——点击右侧命令直接运行，也可以自己敲。 EEPROM 是有状态的：i2cset 写进去的值，i2cget 真的能读回来。

pi@board:~$

终端是模拟的，但命令、参数与输出格式都按真实 i2c-tools 逐字复刻—— 先在这里练熟，再到真板子上敲。

命令 ↔ 波形对照 · 每条命令都是本页某段动画
命令它实际对总线做了什么对应本页
i2cdetect -y 1 对 0x03–0x77 每个地址发「START + 地址」，等第 9 个时钟看有没有人拉 SDA 回 ACK §04 地址字节 + ACK；显示 -- 的就是 NACK
i2cset -y 1 0x50 0x10 0x2a S → 0x50+W → 寄存器号 0x10 → ACK → 数据 0x2A → ACK → P §05「写入 EEPROM」整段动画
i2cget -y 1 0x50 0x10 S → 0x50+W → 寄存器号 → Sr → 0x50+R → 读 1 字节 → 主机 NACK → P §05「读取 EEPROM · 含 Sr」整段动画
i2ctransfer -y 1 w1@0x50 0x10 r1 两条消息放进一次 ioctl(I2C_RDWR)：消息边界自动产生重复起始 Sr，总线全程不释放 同「读取」，但每条消息由你手工拼装
i2cdump -y 1 0x50 循环单字节读，把 0x00–0xFF 全部倒出来（EEPROM 常用） 「读取」波形的连续版

装好了却打不开设备？

/dev/i2c-N 默认归 root:i2c 所有：sudo usermod -aG i2c $USER 后重新登录即可免 sudo；节点由 i2c-dev 模块提供（内核需 CONFIG_I2C_CHARDEV）。

UU 不是故障

i2cdetect 显示 UU 的地址已被内核驱动认领（本例 RTC pcf8563 占 0x51），用户态直接访问会被拒（EBUSY）——这是防止两边互踩的保护；要读数据请走驱动接口（/dev/rtc0、sysfs）。

没有开发板也能练

sudo modprobe i2c-stub chip_addr=0x50 会创建一条纯软件 I²C 总线 + 虚拟 EEPROM，i2c-tools 全套命令照常工作——学命令、调脚本两相宜。

-y 与 SMBus

-y 跳过「Continue? [Y/n]」交互确认，脚本里必加。i2cget/i2cset/i2cdump 走内核 SMBus 接口（字节/字/块读写）——SMBus 是 I²C 的规范化子集。

原生消息用 i2ctransfer

需要重复起始 Sr、一次传输混合读写、或非标准消息长度时，SMBus 接口不够用——i2ctransfer 直接走 I2C_RDWR 消息数组，发出来的波形和 §05 实验室里的一模一样。

扫描有副作用

i2cdetect 默认用 quick-write 探测（向每个地址写 0 位），个别器件（精密 RTC、写保护 EEPROM）可能被意外写入。生产板先核对原理图，或加 -r 改用读字节探测。
