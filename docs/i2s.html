I²S※ 协 议 详 解 · 交 互 式 图 解

三根信号线，传遍整个 Hi-Fi 世界。I²S 是飞利浦（Philips，1986）为芯片间数字音频定下的串行总线标准—— ADC、DAC、Codec、MCU 之间的音频数据都靠它流动。往下滚动，看比特如何被一位一位地搬进扬声器。

01

它是什么，为什么需要它

What & Why

一句话：I²S 是专门为数字音频优化过的同步串行接口——把「数据」和「时钟」分开走，让音频流不需要任何帧头、地址和握手就能连续传输。

I²S（Inter-IC Sound，集成电路内置音频总线）是飞利浦 1986 年定义、1996 年修订的芯片间音频标准， 用来在 PCB 上的芯片之间搬运 PCM 音频采样数据。你手机里的音频 Codec、蓝牙耳机的 DAC、开发板上的 ES8388 / WM8978 / SGTL5000，对外说的都是这门「方言」。

为什么不用现成的 SPI / UART？因为音频是持续的、等时的数据流：SPI 每次传输都要片选和帧同步开销， UART 又是异步的、靠双方波特率猜。I²S 干脆把位时钟 BCK 单独拉一根线连续跑， 接收方「看见时钟沿就采一个比特」，零协议开销；再用 WS 一根线区分左右声道， 立体声天然免费。音量、静音、采样率这些控制则交给并行的 I²C/SPI 控制总线——控制平面与数据平面分离。

数据本身是二进制补码的音频采样值，MSB 在前，左右声道交替出现——正是 DAC 想要的格式，无需任何转换。

FACT / A

时钟与数据分离 BCK

接收方只在时钟沿采样数据线，不数位数、不等帧头，天生抗字节对齐问题。

FACT / B

一根线选声道 WS

WS 电平直接指示当前传的是左还是右，左右声道严格等宽交替，构成一帧。

FACT / C

MSB 先行 · 补码 SD

数据格式与 DAC 内部一致，高位先传意味着即使收发位宽不一致，也能保住音频动态范围。

FACT / D

只管数据，不管控制 CTRL

音量、静音、滤波器配置走旁边的 I²C。I²S 总线上永远是纯粹的音频流。

02

三根信号线（+1 根可选）

Signals

记住三条线的「身份」，I²S 就懂了一大半。每张卡片里都是正在运行的实时波形。

BCKSCK / BCLK / 位时钟CLOCK

位时钟，每一个脉冲搬一个比特。它是总线的「心跳」，永远由主机产生、连续不断。频率由采样率和位宽决定：

f(BCK) = fs × 槽宽(slot) × 2声道
WSLRCK / LRCLK / 字选择FRAME

字选择（帧时钟），电平指示当前声道——低电平 = 左声道，高电平 = 右声道（Philips 定义）。一个完整 L+R 周期 = 音频的一帧：

f(WS) = fs（即采样率）
SDSDATA / DIN / DOUT / 串行数据DATA

串行数据，左右声道时分复用在同一根线上。每个采样值以二进制补码、MSB 在前发送；发送端在 BCK 下降沿更新，接收端在上升沿锁存。

MCLKSYSCLK / 主时钟（可选）AUX

不是 I²S 规范的正式成员，但很多 Codec 离了它活不了：内部 Δ-Σ 调制器、PLL、滤波器都靠它吃饭。通常由主控提供，且必须与 fs 同步：

f(MCLK) = 256 × fs（最常见）

04

四种数据格式 · 只差一个「对齐」

Data Formats

收发双方都要回答同一个问题：数据字段相对于 WS 边沿放在哪？答案不同，就是不同的「格式」。下面以 槽宽 32 BCK、字长 16 bit 为例（最常见的配置之一）。

PHILIPS

标准 I²S

I²S STANDARD
官方格式：MSB 延迟 1 个 BCK 出现在 WS 边沿之后，剩余槽位补 0（或符号扩展）。兼容性最好，是「不说格式时」的默认假设。
LJ

左对齐

LEFT-JUSTIFIED
MSB 与 WS 边沿严格对齐，没有那 1 拍延迟。省掉一个时钟、更简单，很多 DAC 的原生格式。与标准 I²S 仅差 1 BCK——听感却是「满噪声」。
RJ

右对齐

RIGHT-JUSTIFIED
LSB 对齐槽位末端，数据靠右停放，前面补 0。当字长 = 槽宽时与左对齐完全相同；较少见，部分老 Codec 支持。
DSP

DSP / PCM 模式

TDM READY
WS 变成仅 1 个 BCK 宽的帧同步脉冲，脉冲后紧跟数据，没有「左右」概念——通道按时隙依次排开。TDM 多通道共享总线（2/4/8 声道）都基于它。
致命细节：主控与 Codec 的格式必须一致。配置里叫 I2S / LJ / RJ / DSP / PCM（STM32）、 Standard / MSB / LSB（ESP-IDF）、fmt（Linux ASoC）。错配的典型症状：满「沙沙」噪声、 音量减半、直流偏移，或左右声道互换。若双方格式寄存器都有，逐项核对「延迟几个 BCK + 对齐方向」。
05

主从模式 · 谁给时钟谁说了算

Master / Slave

I²S 里「主机」的定义极其朴素：谁输出 BCK 和 WS，谁就是主机。SD 的方向与主从身份无关。

架构 AMCU 做主机

MCU 的 I²S 外设产生 BCK/WS，Codec 只听令。最常见于嵌入式：ESP32、STM32、树莓派 驱动 ES8388 等小板。 MCU 若无 MCLK 引脚，可用 PLL 或独立晶振喂给 Codec。

架构 BCodec 做主机

USB 音频解码器、蓝牙模块常用：专用音频芯片自产自销 BCK/WS，MCU 退化为从机只收发数据。 好处是时钟抖动（jitter）更小，DAC 信噪比更高。

铁律一总线一主机

两边都当主机 = 时钟打架，波形畸变；两边都当从机 = 总线死寂无声。调试「完全没声」时先用示波器看 BCK 是否在跳、再看方向对不对。

Linux 上的 I2S · 命令实战

Linux Cheat Sheet

树莓派和绝大多数嵌入式 ARM Linux 的 I2S 都由 ALSA / ASoC 子系统管理：数据面（本页 03 节的波形）走 I2S 驱动， 控制面（音量、格式寄存器）走 I2C——正好对应 01 节「控制平面与数据平面分离」。 点击任意命令行即可复制。（以下在树莓派 / 通用嵌入式 Linux 上适用；桌面 x86 的板载声卡一般不走 I2S。）

ls — 你的 I2S 声卡在哪
$ aplay -l # 列出播放设备
card 1: VoiceHat [snd_rpi_googlevoice_hat], device 0
$ arecord -l # 列出录音设备
$ cat /proc/asound/cards # 声卡总览
0 [HDMI ]: hdmi - HDMI Audio
1 [VoiceHat]: snd_rpi_googlevoice_hat - Voice Hat
play / rec — 数据面收发
$ speaker-test -c 2 -r 48000 -D plughw:CARD=1
# 轮流报 "front left / front right" —— 验证 WS 左右声道是否正确
$ aplay -D plughw:CARD=1 test48k.wav
$ arecord -D hw:1,0 -f S16_LE -r 48000 -c 2 rec.wav
# -f S16_LE / S24_LE / S32_LE ←→ 03 节的「字长」
hw_params — 验证协议参数
$ cat /proc/asound/card1/pcm0p/sub0/hw_params
status: RUNNING
format: S32_LE ← 字长 / 槽宽 32 bit
rate: 48000 (48.000 kHz)
channels: 2
→ BCK = 48000 × 32 × 2 = 3.072 MHz，拿示波器对！
amixer — 控制面走 I2C
$ alsamixer -c 1 # 交互调音量（= I2C 写 codec 寄存器）
$ amixer -c 1 scontrols # 列出该 codec 的控件
$ amixer -c 1 cset name='Master Playback Volume' 80%
$ i2cdetect -y 1 # 扫 I2C 总线找 codec 地址
0 1 2 … f
10: 10 -- -- -- -- -- -- # 0x10=ES8388 · 0x1A=WM8978 · 0x0A=SGTL5000
树莓派 — 启用 I2S 接口
# /boot/firmware/config.txt（旧系统在 /boot/config.txt）
dtparam=i2s=on
dtoverlay=googlevoicehat-soundcard
# 其他常见 I2S 声卡 overlay：
# dtoverlay=hifiberry-dac
# dtoverlay=adafruit-max98357a
$ sudo reboot
dmesg — 出问题先看内核日志
$ dmesg | grep -iE 'asoc|i2s|snd|es8388'
[ 3.812345] es8388 1-0010: ASoC: codec registered
[ 3.820001] snd-es8388 es8388-card: card registered
$ cat /proc/asound/card1/pcm0p/sub0/status
state: RUNNING xrun: 0 # 欠载计数，爆音/断音时增长
DTS — 自定义声卡：simple-audio-card
/* 设备树片段：把 SoC 的 I2S 控制器与 codec 绑成一张声卡（板级 .dts 或 overlay）*/
&i2s1
{ status = "okay"; };
sound {
compatible = "simple-audio-card";
simple-audio-card,name = "ES8388-Card";
simple-audio-card,format = "i2s"; /* i2s | left_j | right_j | dsp_a | dsp_b ←→ 04 节四种格式 */
simple-audio-card,bitclock-master = <&cpu_dai>; /* 谁给 BCK 谁是主机 ←→ 05 节 */
simple-audio-card,frame-master = <&cpu_dai>; /* WS 同上 */
simple-audio-card,cpu { sound-dai = <&i2s1>; };
simple-audio-card,codec { sound-dai = <&es8388>; };
};
两个高频坑：① 设备树 format 与 codec 驱动里的格式不一致，就是 09 节的「沙沙噪声」在 Linux 下的样子； ② ALSA 常用 S32_LE 做容器——系统以 32 拍槽传 16 位有效数据（03 节动画的常见配置）， hw_params 里看到 32 不代表音源真是 32 位。自定义声卡建议先用 simple-audio-card 通用绑定， 复杂时钟拓扑再考虑 audio-graph-card 或写原生 machine driver。

踩坑指南 · 症状 → 病因

Troubleshooting

调 I²S 的时间几乎都花在下面这些地方。按症状对号入座。

左右
互换
WS 极性反了 / 格式错位 1 bit

声像颠倒多半是 WS 高低电平定义对调，或 LJ↔I²S 错配导致数据窗偏移了一拍。检查 WS 极性（有的驱动叫 ws_polarity）与格式寄存器。

沙沙
噪声
数据格式不匹配（头号原因）

I²S vs LJ 只差 1 个 BCK，人耳听就是持续白噪。逐一核对：格式 / MSB-LSB 顺序 / 槽宽 vs 字长 三项，主控和 Codec 两边都要对。

完全
无声
没人产生时钟 / 主从冲突

示波器先看 BCK、WS 有没有波形、方向对不对。两边都配成从机总线就是死的；两边都当主机会电平打架。别忘了部分 Codec 需要 MCLK 才肯启动。

变调
加速
BCK 与 fs 不匹配

播放「快进小嗓门」= 每帧实际比特数和接收方预期不一致（比如 32 槽被配成 16 槽）。用 06 节公式核对 BCK = fs × slot × 2。

量化
噪声
字长被截断

24-bit 音源塞进 16-bit 槽，只把低 16 位发出去了——高 8 位动态全丢。确认 字长 word length 与数据移位方向。

SNR
打折
时钟抖动 & 走线

BCK/MCLK 的 jitter 直接换算成 DAC 底噪。时钟线短而等长、远离开关电源；必要时让更靠近晶振的一方做主机。

时好
时坏
没共地 / 电平不匹配

I²S 只在 3.3V（老器件 5V）同电平间直连；跨电平要电平转换。共地是前提——「偶尔爆音」八成是地弹。
